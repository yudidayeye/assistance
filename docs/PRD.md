## 2. 产品概述

“理解”是一款轻量级、模块化的个人工具应用，目前提供以下三个核心模块：

1. **周期记账**：以发薪周期为单位记录本金、追加、分类支出、余额和大额收支。
2. **生理期记录**：记录经期日期与备注，并基于历史数据提供周期预测和统计。
3. **密码保险箱**：按分类管理账号密码，支持主密码、密码字段加密和 Windows 桌面快捷方式。

应用的核心业务数据保存在设备本地 SQLite 数据库中，不提供账号系统、云端业务数据同步或遥测。用户可以通过 JSON 文件进行备份和恢复，也可以在可信局域网内点对点传输备份。

## 3. 产品原则与边界

### 3.1 产品原则

- **本地优先**：核心业务数据默认仅保存在当前设备。
- **轻量聚焦**：围绕明确的个人场景提供必要功能，避免演变为复杂平台。
- **模块化**：模块可独立启用、停用和排序，停用模块不删除数据。
- **透明可控**：导入、同步、清除数据等高影响操作必须由用户确认。
- **隐私谨慎**：不夸大加密范围，并对备份、局域网同步和主密码风险给出明确提示。

### 3.2 当前产品边界

- 不提供注册、登录、多用户或云账号能力。
- 不提供云同步、远程备份或跨互联网点对点同步。
- 不采集业务数据，不集成广告、分析或遥测 SDK。
- 版本更新检查会访问 GitHub Release；这是产品当前明确存在的联网行为。
- 生理期预测只用于个人记录和趋势参考，不构成医疗建议。
- 密码保险箱仅加密符合条件的密码字段，不代表整个数据库或所有条目字段均已加密。

## 4. 目标用户与核心场景

### 4.1 目标用户

- 希望按工资周期而非自然月管理日常支出的用户。
- 希望在本地记录生理周期并查看趋势的用户。
- 希望在个人设备上集中保存常用账号密码的用户。
- 重视数据本地保存、愿意自行管理备份的用户。

### 4.2 核心场景

1. 用户创建一个发薪周期，按阶段记录支出、追加和余额，复盘资金变化。
2. 用户在日历中记录经期开始与结束日期，查看预测日期和统计结果。
3. 用户设置主密码，创建保险箱分类并保存账号密码。
4. 用户导出完整 JSON 备份，在重装、换机或另一台受信任设备上导入。
5. 用户在同一可信局域网内，将备份发送到另一台正在运行本应用的设备。

## 7. 周期记账

### 7.1 模块定位

周期记账以发薪周期为核心单位，帮助用户观察一个收入周期内的本金、阶段支出、余额及大额收支，不替代完整财务或会计系统。

### 7.2 周期管理

用户可以：

- 创建、编辑、关闭和删除周期。
- 按发薪日自动计算周期日期。
- 使用自定义开始和结束日期。
- 查看当前周期和历史周期。
- 查看周期详情、余额趋势、支出构成和月度聚合信息。

日期规则：

- 默认发薪日为每月 10 日，可设置为 1 至 31 日。
- 当目标月份不存在所选日期时，使用该月最后一天。
- 自动周期的结束日期为下一发薪日前一天。
- 不允许创建与已有周期日期重叠的新周期。
- 当前周期结束日期早于今天时，系统应自动将其关闭。

### 7.3 阶段管理

- 创建周期后，系统按自然周自动拆分阶段。
- 第一阶段从周期开始日持续至当周周日。
- 中间阶段为周一至周日。
- 最后一阶段截止周期结束日。
- 用户可以编辑阶段当前记录日期、余额、追加和支出。

### 7.4 金额记录

周期记账支持：

- 周期初始本金。
- 阶段内普通追加。
- 阶段内分类支出。
- 用户手动录入的阶段余额。
- 周期级大额追加和大额支出。

当前支出分类包括生活、购物、工作、娱乐、大餐和其他，并兼容历史分类值。

阶段生活支出可以根据阶段本金、已记录分类支出、其他支出和用户录入余额倒推。大额追加和大额支出独立展示，不计入日常总本金和日常总支出，避免扭曲日常消费统计。

### 7.5 历史与统计

- 显示历史周期列表和周期详情。
- 展示余额趋势、分类支出占比和月度支出等聚合结果。
- 无当前周期时，模块摘要提示用户创建周期。
- 有当前周期时，摘要显示日期范围以及余额或支出概览。

### 7.6 验收要点

- 日期自动计算正确处理不同月份天数和跨年场景。
- 重叠周期无法保存，并向用户说明原因。
- 阶段拆分覆盖整个周期，阶段间无遗漏、无重叠。
- 删除周期时，与其关联的阶段和收支记录一并删除。
- 大额收支与日常统计口径保持分离。

## 8. 生理期记录

### 8.1 模块定位

生理期记录用于个人日期记录、趋势观察和基础预测，不用于诊断、治疗、避孕决策或其他医疗用途。

### 8.2 记录管理

用户可以：

- 在日历中记录经期开始日期。
- 为记录补充结束日期和备注。
- 编辑或删除已有记录。
- 将没有结束日期的记录视为“进行中”。
- 查看历史记录和周期统计。

经期持续天数按开始日期和结束日期之间的自然日计算，首尾日期均计入。

### 8.3 周期计算与预测

- 系统根据相邻经期开始日期计算历史周期长度。
- 没有历史记录时不提供预测。
- 历史数据不足时采用默认周期长度进行估算。
- 数据达到要求后，优先参考近期有效周期进行加权计算。
- 预测结果包括下次经期、排卵日、易孕期和预测经期范围。
- 预测日期应推进到今天或未来，不显示已经完全过期的“下次经期”。

所有预测页面必须明确提示：预测仅基于历史记录进行估算，仅供参考，不构成医疗建议。周期异常或存在健康疑问时，应建议用户咨询专业医疗人员。

### 8.4 摘要与统计

- 模块摘要显示预测的下次经期日期和当前周期天数。
- 统计页展示可由现有历史记录计算的周期信息。
- 修改或导入记录后，应重新计算周期长度和预测结果。

### 8.5 验收要点

- 结束日期不得早于开始日期。
- 持续天数包含开始和结束当天。
- 新增、编辑、删除和导入记录后，周期长度重新计算。
- 历史数据不足时不得误导用户认为预测具有高准确性。
- 无记录时不生成无依据的预测日期。

## 9. 密码保险箱

### 9.1 模块定位

密码保险箱用于在本地分类保存常用账号密码。安全设计以降低明文密码暴露风险为目标，但不应描述为完整数据库加密或绝对安全存储。

### 9.2 首次设置与解锁

- 首次进入时要求设置主密码。
- 后续访问加密数据前需要验证主密码。
- 主密码和派生密钥仅在当前解锁会话内保留。
- 离开分类详情、应用进入后台或模块关闭时，应锁定会话。
- 主密码不提供找回能力；遗忘主密码可能导致加密密码无法恢复。

### 9.3 分类管理

用户可以：

- 创建、编辑和删除分类。
- 设置分类名称、图标和排序。
- 将分类设为“加密”或“不加密”。
- 调整分类加密状态，并迁移已有条目的密码字段。

规则：

- 新分类默认启用加密。
- 加密分类中的密码字段以密文保存。
- 不加密分类中的密码字段以明文保存。
- 分类包含条目时，如果更改加密状态需要密钥而会话已锁定，应先要求用户解锁。
- 删除分类时，其条目一并删除，并必须进行确认。

### 9.4 条目管理

条目支持：

- 标题。
- 用户名。
- 密码。
- 多条结构化备注。
- 创建、编辑、删除、查看和排序。
- 复制标题、密码和备注内容。

兼容旧版普通文本备注时，应将其作为“其他”类型备注展示，不丢失原内容。

### 9.5 可见性与锁定规则

- 加密分类未解锁时，不显示密码明文。
- 解锁仅在当前内存会话有效，不绕过后续锁定规则。
- 分类详情页退出、应用进入后台或 inactive 状态时应锁定。
- Windows 桌面快捷方式只负责直达指定分类，不能绕过主密码验证。

### 9.6 加密范围说明

当前加密范围必须如实表述：

- 加密分类中的**密码字段**使用加密后存储。
- 标题、用户名、备注、分类名称、分类图标等元数据为数据库明文字段。
- 不加密分类的密码字段也是明文。
- 导出的备份可能包含明文元数据、未加密分类密码以及解密所需的加密参数，因此属于敏感文件。

### 9.7 验收要点

- 正确主密码可以解锁，错误主密码不得泄露密码明文。
- 新加密条目使用独立随机盐和 IV。
- 切换分类加密状态后，已有条目的密码可正常读取且存储形式符合目标状态。
- 锁定后清理内存中的主密码和派生密钥。
- 快捷方式直达分类时仍执行正常的主密码校验。

## 10. 数据备份与恢复

### 10.1 导出

- 用户可以导出 UTF-8 编码的 JSON 备份。
- 备份包含应用设置及三个模块的业务数据。
- 导出过程不应修改现有数据。
- 应提示用户将备份保存在安全位置，避免通过不可信渠道传播。

### 10.2 导入

- 用户选择 JSON 文件后，系统先解析、预览和校验，再执行导入。
- 高于当前应用支持版本的备份应拒绝导入，并提示升级应用。
- 导入在单个数据库事务内完成，失败时不应留下部分导入结果。
- 导入采用按记录合并策略，相同 ID 的记录由备份内容覆盖，而不是默认清空整个数据库。
- 导入完成后重新加载设置、主题和模块摘要。

### 10.3 Vault 兼容保护

- 本地已设置主密码时，导入不得覆盖本地主密码。
- 当本地主盐与备份主盐不同，且备份含依赖旧主盐、没有独立盐的旧格式条目时，应跳过整个 Vault 数据导入，避免导入后无法解密。
- Vault 因兼容保护被跳过时，其他模块数据仍可正常导入，并向用户说明结果。
- 不承诺所有历史备份在任意主密码环境下都能无条件恢复。

## 11. 局域网同步

### 11.1 功能定位

局域网同步是在同一局域网内点对点传输完整 JSON 备份，不是云同步，也不提供持续的双向数据一致性。

### 11.2 使用流程

1. 接收端打开数据同步页面并启动接收服务。
2. 发送端发现同一局域网中的可用设备。
3. 用户选择目标设备并发送当前完整备份。
4. 接收端展示导入请求，并由用户确认或拒绝。
5. 用户确认后，接收端按普通导入规则校验并合并数据。
6. 临时文件在完成、拒绝或失败后删除。

### 11.3 安全边界

- 当前局域网同步没有身份认证、配对码或传输层加密。
- 仅允许在用户信任的家庭或私人局域网中使用。
- 不建议在公共 Wi-Fi、公司访客网络或其他不可信网络中启用。
- 即使 Vault 密码字段为密文，备份中的标题、用户名、备注及其他元数据仍可能敏感。

## 12. 设置、主题与版本更新

### 12.1 设置能力

当前设置页提供：

- 模块管理。
- 主题设置。
- 数据导入与导出。
- 局域网数据同步入口。
- 清除业务数据。
- 当前版本展示和检查更新。
- 隐私声明、免责声明静态条目。

“清除业务数据”会删除所有 `mod_%` 模块表中的业务记录，包括周期记账、生理期记录和 Vault 数据。执行前必须二次确认；清除后 Vault 会回到锁定状态。应用设置不属于该操作的业务表清理范围。

### 12.2 主题

提供四套内置主题：

| 主题标识 | 中文名称 | 主色 |
| --- | --- | --- |
| `softNight` | 柔夜 | `#0A82FD` |
| `morningMist` | 晨雾 | `#8AADB8` |
| `leafWhisper` | 叶语 | `#9CAD8A` |
| `flowerMist` | 花雾 | `#C9A0AA` |

主题切换应即时生效并持久化。具体颜色 Token、组件状态和布局规范见 `docs/UI.md`。

### 12.3 版本更新

- 用户可以手动检查 GitHub Release 中的最新版本。
- 系统比较本地版本与远端版本，仅在发现更高版本时提示更新。
- Android 优先选择与设备 ABI 匹配的 APK；Windows 优先选择安装程序。
- 无法找到可信安装包时，降级打开 GitHub Release 页面。
- 下载完成后调用系统安装器，安装权限和确认流程遵循操作系统要求。
- 检查更新会访问 GitHub，但不得上传核心业务数据或用于遥测。

## 13. 隐私、安全与风险提示

- 核心业务数据存储于本地 SQLite。
- JSON 备份不等同于安全加密容器，应由用户自行妥善保存。
- 局域网同步只适合可信网络。
- Vault 仅对特定密码字段加密，其他字段可能为明文。
- 主密码遗忘可能导致加密密码不可恢复。
- 删除数据、删除 Vault 分类、导入备份等操作必须清晰说明影响范围。
- 生理期预测不构成医疗建议，不得给出诊断或准确率承诺。
- 应用不得新增业务数据云同步、广告追踪或遥测，除非未来产品范围和隐私政策经过明确评审与更新。

## 14. 非功能需求

### 14.1 可用性

- 核心操作提供明确的成功、失败和风险反馈。
- 删除、覆盖、导入、清除等不可逆或高影响操作必须确认。
- 页面和交互遵循 `docs/UI.md`，保证主题一致性和基础无障碍可读性。

### 14.2 性能

- 常规本地查询和页面切换不应出现明显阻塞。
- 数据导入、密码派生和加解密等耗时操作应显示可理解的处理中状态。
- 同步设备过期、请求超时和临时文件清理应自动完成。

### 14.3 可靠性

- SQLite 外键约束应保持启用。
- 关联数据删除应遵循级联规则。
- 导入必须使用事务，避免部分成功导致数据不一致。
- 数据库升级应保留历史数据，并兼容已发布版本的迁移路径。

### 14.4 兼容性

- Android 为主要移动平台。
- Windows 支持桌面运行、安装包和 Vault 分类快捷方式。
- iOS 暂不作为当前发布目标。

## 15. 总体验收标准

- 应用能够按规定顺序完成数据库、模块、设置、主题和路由初始化。
- 三个模块首次默认启用，并可停用、恢复和排序。
- 模块核心增删改查在重启应用后仍保持一致。
- JSON 导出包含当前 schema 支持的数据，导入校验和事务行为符合规格。
- 局域网发送必须经接收端确认后才能导入。
- Vault 锁定、解锁、分类加密切换和快捷方式行为符合安全边界。
- 更新检查只访问 GitHub Release，不上传业务数据。
- 清除业务数据覆盖所有模块表，并在操作后刷新界面和锁定 Vault。
- 所有用户可见文案使用简体中文，技术标识符按项目约定保留英文。

## 16. 当前范围与后续候选

以下能力当前尚未实现，不应在发布说明或产品介绍中描述为已完成：

- 通知管理。
- 帮助与反馈交互页面。
- iOS 发布支持。
- 云同步、在线账号或远程备份。
- 局域网同步身份认证、配对码和传输加密。
- 完整数据库加密或 Vault 全字段加密。

后续是否实现上述能力，应单独进行需求、安全和隐私评审，不自动视为当前产品路线承诺。
