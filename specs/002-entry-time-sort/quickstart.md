### 1.1 单元测试（纯函数契约）


## 二、数据库迁移验证

### 2.1 升级路径（US4 / SC-003 的核心）

这是本特性**风险最高**的一环，必须真机验证，不能只靠单测。

```bash
# 1. 在改动前的代码上运行应用（git stash 或切到改动前的 commit）
flutter run -d windows
# 2. 在「周期记账」里建一个周期 + 阶段，录入若干条支出与追加（记下条数与顺序）
# 3. 退出应用，备份数据库文件（见下）
# 4. 切回改动后的代码
flutter run -d windows
```

**数据库文件位置**：
- Windows：`%APPDATA%\<org>\<app>\toolbox.db`（随 `path_provider` 的 `getApplicationDocumentsDirectory()` / `getApplicationSupportDirectory()` 而定，实现时可打印路径确认）
- Android：应用私有目录，需 `adb` 或从应用内导出备份

**验证点**：

| # | 检查 | 期望 |
| :--- | :--- | :--- |
| 1 | 条目条数 | 与升级前**逐条一致**，无丢失 |
| 2 | 列表顺序 | 与升级前**逐条一致**，无错位 |
| 3 | 新增条目 | 可正常新增（说明新列已就位） |
| 4 | 应用启动 | 无异常、无白屏、无「数据库版本不匹配」报错 |

**兜底手段**：若第 4 项失败，数据库文件仍在原位。**先复制一份留档**，再排查 `_migrateToV18`。

### 2.2 全新安装路径

```bash
# 删除应用数据目录（或卸载重装），确保 toolbox.db 不存在
flutter run -d windows
```

**验证点**：新建周期 + 阶段，新增一条填写了日期的条目 → 保存成功且日期显示正常。说明 `_onCreate` 的 DDL 已同步加列（**两条路径都改到**是常见遗漏点）。

## 三、手工功能验证

### 3.0 SC-002 —— 本特性的判定性验收

**这是用户亲口给出的样例，必须逐字复现。**

在**同一天内**、于**同一个表单**（如「阶段详情页 → 个人支出」）依次录入 4 条：

| 次序 | 金额/描述 | 时间字段 |
| :--- | :--- | :--- |
| 第 1 条 | 任意 | **不填** |
| 第 2 条 | 任意 | 填 **10月9日** |
| 第 3 条 | 任意 | **不填** |
| 第 4 条 | 任意 | 填 **10月8日** |

**期望列表顺序（从上到下）**：第 1 条 → 第 4 条 → 第 2 条 → 第 3 条，即 **`0-3-1-2`**。

> 若结果不是 `0-3-1-2`，先检查单测（§1.1）是否全绿。单测过了而这里不过，问题在 UI 到 service 的接线（日期没传下去，或新增没走 `_rescheduleXxx`）。

### 3.1 US1 —— 可选时间字段（6 个表单全覆盖，FR-001）

逐个验证下列 6 处，每处都要展开新增表单：

| # | 页面 | 表单 |
| :--- | :--- | :--- |
| 1 | 阶段详情页 | 追加 |
| 2 | 阶段详情页 | 个人支出 |
| 3 | 阶段详情页 | 其他支出 |
| 4 | 大额页 | 大额追加 |
| 5 | 大额页 | 购物支出 |
| 6 | 大额页 | 其他支出 |

**每个表单验证**：

| 检查 | 期望 |
| :--- | :--- |
| 不填时间的操作步骤 | 与改动前**完全相同**（SC-001，零新增必填项/零新增点击） |
| 填写时间后提交 | 保存成功，列表行内显示该日期 |
| 提交后表单状态 | 金额/描述/时间**全部清空**（避免连续新增时把上一条的日期带下去） |
| 已选日期后点「清除」 | 恢复为未选状态，提交后条目**无日期标记** |

### 3.2 US2 —— 自动落位（FR-003 / FR-004）

| # | 操作 | 期望 |
| :--- | :--- | :--- |
| 1 | 在既有列表中新增一条**较早**日期的记录 | 落在列表中对应位置，**不是**末尾 |
| 2 | 新增一条**不填**时间的记录 | 追加到末尾（与改动前一致） |
| 3 | 编辑一条已有记录，把日期改**更早** | 条目重新落到更靠前的位置 |
| 4 | 编辑一条已有记录，把日期**清空** | 条目**停在原地不动**，并恢复为可任意拖动 |
| 5 | 新增一条**未来**日期的记录 | 允许，落到末尾方向（不做拦截） |
| 6 | 新增一条**不属于本阶段/周期范围**的日期 | 允许（不做跨表校验） |

### 3.3 US3 —— 拖拽（FR-011 / SC-005 / SC-006）

| # | 操作 | 期望 |
| :--- | :--- | :--- |
| 1 | 拖动一条**未填时间**的记录到列表**任意**位置 | 生效，刷新后保持 |
| 2 | 拖动一条未填时间的记录，**穿过**若干已填日期的条目（含拖到两条有日期条目**之间**） | 生效，**不被拒绝** |
| 3 | 拖动一条**已填日期**的记录到**日期晚于它**的条目之后 | **不生效**，1 秒内出现明确提示 |
| 4 | 拖动一条已填日期的记录到**日期早于它**的条目之前 | 同上 |
| 5 | 在**同一天**的多条条目之间调整先后 | 生效，刷新后保持 |
| 6 | 拖动一条已填日期的记录，且列表中**不存在同日邻居** | 允许移动（前后找不到更晚/更早者即通过） |
| 7 | 在**筛选态**下（从报表页饼图点中某分类进入） | 拖拽**被禁用**（既有行为，保持不动） |
| 8 | 删除任意一条记录 | 其余条目**相对顺序不变** |

> 第 3/4 项若表现为「拖了但没反应」且**没有提示**，判为不通过——FR-011 明确禁止这种状态。
> 第 1/2 项若**任何一次被拒绝**，直接判为不通过（SC-005 要求「无一例被拒绝」）。

### 3.4 统计口径不受影响（FR-010）

| # | 操作 | 期望 |
| :--- | :--- | :--- |
| 1 | 给若干条记录填/改/清时间 | 阶段小计、周期合计、余额**全部不变** |
| 2 | 同上 | 报表页饼图的各分类构成**完全不变** |

### 4.1 旧备份导入

1. 用**改动前**的应用导出一份 JSON 备份（不含 `entry_date` 字段）
2. 用**改动后**的应用导入

**期望**：导入成功（不报错、不被结构校验拒绝）；这些条目按「未填写时间」处理，顺序按备份中的 `sort_order` 还原。

### 4.2 新备份往返

1. 用**改动后**的应用：录入若干条带日期的记录 → 手工拖拽调整顺序 → 导出备份
2. 清空数据（或用另一台设备）→ 导入该备份

**期望**：**时间与列表顺序都被完整还原**，与导出前逐条一致。

> ⚠️ 这一项会在**大额追加**列表上暴露 [data-model §4.3](./data-model.md#43-备份导入的既有缺陷修复) 描述的既有缺陷（导入 SQL 遗漏 `sort_order`）。若大额追加的顺序在往返后被打乱，说明该修复没做。
>
> **不要**只在支出列表上验证——支出列表的导入路径本来是好的，掩盖不了这个缺陷。

### 4.3 结构校验不误伤

1. 组装一份只含 `period_book_expenses`（无 `entry_date`、无 `sort_order`）的极简 JSON
2. 导入

**期望**：不因缺字段而报错。

## 六、常见失败模式速查

| 症状 | 最可能的原因 |
| :--- | :--- |
| 新装用户新增条目报「no such column: entry_date」 | 只改了 `_onUpgrade` 没改 `_onCreate`（或反之） |
| 升级用户报同样错误 | `_migrateToV18` 没在 `_onUpgrade` 中挂载，或版本号没递增 |
| 填了日期但条目仍追加到末尾 | `addXxx` 插入后没调 `_rescheduleXxx`，或 `_rescheduleXxx` 在 `entryDate == null` 之外也早退了 |
| 拖拽「拖了没反应」且无提示 | `onReorder` 拒绝了但没弹 SnackBar（SC-006 不通过） |
| 无日期条目有时被拒绝拖动 | `canReorder` 的 `moved == null` 分支没提前返回，走进了日期检查 |
| 向上拖的落点比预期少一位 | `normalizeReorderIndex` 没做，或做了两次 |
| 日期显示成 `2026-1-5` 且排序错乱 | `formatEntryDate` 没有零填充，破坏了字典序 |
| 历史条目顺序被打乱 | `ORDER BY` 里混进了 `entry_date`，或迁移误触了 `sort_order` |
| 大额追加导入后顺序乱掉 | §4.3 的 `sort_order` 缺陷未修 |
| 导入旧备份后无日期条目全跑到列表最前 | 导入时写了 `map['entry_date'] ?? ''`（空串而非 `null`） |
