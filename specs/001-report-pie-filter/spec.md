# Feature Specification: 历史记录报表饼图点击联动周期卡片筛选

**Feature Branch**: `20260920-130359-report-pie-filter`

**Created**: 2026-09-20

**Status**: Draft

**Input**: User description: "历史记录页面，报表，饼图点击，需要增加功能：1. 日常：点击饼图指定分类后，下方的周期卡片展示对应分类的支出明细，再次点击去掉筛选；2.大额：点击饼图指定分类后，下方的周期卡片筛选对应分类的支出展示，再次点击去掉筛选：3.合计：下方的周期卡片展示对应分类的日常和大额明细，再次点击去掉筛选"

## Clarifications

### Session 2026-09-20

- Q: 用户筛选后向下滚动浏览周期卡片时，饼图已经滚出屏幕，此时他靠什么知道正处于筛选状态、又该从哪里取消筛选？ → A: 饼图扇区高亮，同时在列表滚动时保持一条筛选标签吸顶常驻，标签上显示分类名并提供关闭按钮。
- Q: 饼图是否会出现两个都叫「杂项」的扇区（真实的杂项支出分类 vs 显示名同样被映射为「杂项」的结余）？ → A: 不会。饼图渲染时已排除结余，结余不参与渲染与图例；「杂项」即结余口径（本金减去各项支出的倒推残值），图例中只有一个杂项扇区。
- Q: 「杂项」的金额完全由倒推残值构成、没有任何一条支出记录可列，与「逐条支出记录」的呈现方式直接冲突，该扇区如何处理？ → A: 可筛选；卡片显示小计并附一行说明，标明该金额来自未逐条记录的部分，不渲染明细条目、不显示「查看全部」入口。
- Q: 在「日常」视图选中分类后切到大额视图再切回，筛选应该还在还是已清空？ → A: 切换视图即清空筛选，切回后一律回到未筛选状态；筛选不跨视图传递。
- Q: 占比极小的分类在饼图上只是一道窄弧、几乎点不中，图例行是否也可点击筛选？ → A: 图例行与扇区都可点击，二者完全等价，均可选中或取消筛选。
- Q: 日常视图的筛选是「年 → 月 → 阶段」三层，阶段变化会连饼图的分类集合一起换掉；此时已选中的分类筛选如何处理？ → A: 与年月一视同仁——保留筛选、按新阶段重新计算该分类的小计与明细；若新阶段该分类完全没有金额，则自动取消筛选。年、月、阶段统一视为"范围变更"，只适用一条规则。
- Q: 点击筛中一个分类后，饼图与图例各应有什么视觉反馈？ → A: 选中扇区高亮，图例中对应分类所在行同步高亮；其余扇区与图例行保持原样，不整体淡化。两个入口的选中态必须一致。
- Q: 大额视图的卡片当前已全量逐条列出每一笔记录（无条数上限），筛选后是否仍套用「限 3 条 + 查看全部」？ → A: 套用，三个视图统一规则。已知取舍：该视图下会出现"筛选后的卡片比筛选前更短"，这是为聚焦付出的代价，换取三视图一致的高度表现与一致的交互模型。
- Q: 日常视图的「其他消费」当前没有对应扇区、无法被筛中，这个缺口是否补齐？ → A: 补齐。日常饼图新增「其他」扇区，使分类口径与卡片第二行完全对齐。已知代价：该图既有的金额构成随之改变，补上后各扇区之和覆盖该周期总支出（此前「其他消费」整体不在饼图内）。
- Q: 一笔其他消费（子类选了"购物"）在饼图里应算什么？ → A: 一律归入「其他」扇区，不按子类区分、不并入子类同名的普通分类；三个视图的归类口径必须一致。已知代价：合计与大额饼图的既有显示随之改变（其他消费不再混入普通分类扇区）。
- Q: 筛选生效后，卡片第二行的汇总列（日常的「个人消费 | 其他消费」、合计的「日常消费 | 大额记录」）应该被筛选结果顶掉，还是保留在筛选结果上方作对照？ → A: 保留。筛选结果追加在汇总信息下方，第一行主金额与第二行汇总列均原样保留、数值口径不变。已知代价：卡片整体变高；汇总列与筛选明细口径不同，会出现「个人消费 ¥0 / 购物 ¥320」这类并列，需由用户自行分辨。
- Q: 大额卡片在筛选状态下，没有分类归属的「大额追加」分组应跟随明细区一起消失，还是保留在筛选结果里？ → A: 一起消失。筛选后大额卡片只剩所选分类的小计与明细条目，三个原分组全部被替换。已知代价：第一行净额中"追加"那一半在筛选状态下没有可见的明细出处。
- Q: 点「查看全部 N 条」之后，应该看到该周期的全部记录（不区分分类），还是被直接送到筛中的那个分类上？ → A: 都不跳。**既不跳页面也不弹窗，直接在原卡片内展开**，列出该分类在这一个周期下的全部条目。此选择使原 SC-004（卡片高度不随条目数增长）不再成立，已改写为"未展开时高度恒定、仅主动展开的卡片才随条目数增长"。
- Q: 展开卡片时是允许同时展开多张，还是一展开新的就自动收起旧的那张？ → A: 自由多张。每张卡片的展开状态相互独立，允许多张同时保持展开，以便并排对比不同周期的同一分类明细。已知代价：用户连点若干张后列表会被撑长，但这是其主动操作的结果。
- Q: 筛选「其他」之后，每行明细旁边要不要标出这笔钱录入时选的子类（购物 / 生活 等）？ → A: 不显示。明细行只给描述与金额，不出现任何分类或子类标签，子类信息仅保留在数据库里。理由是避免「其他·生活」与真正记在「生活」分类下的记录带上完全相同的标签，同时与明细行既有的写法保持一致。
- Q: 当用户在筛选栏选中了某个「阶段」时，被筛选分类的卡片小计该按所选阶段统计，还是按整个周期统计？ → A: **卡片跟随阶段**——筛选生效时，卡片小计与明细只统计属于所选阶段的支出，与饼图口径一致（饼图在选中阶段时本就只统计该阶段），使 SC-003 在选阶段时依然成立。理由是用户选阶段的意图本就是"只看这个阶段"，筛选后却列出其他阶段的记录会出乎意料。已知代价：同一张卡片在筛选态与未筛选态下的口径不同（未筛选时仍按整个周期展示）；大额与合计视图的饼图不受阶段选择影响，故这两个视图筛选后仍按整个周期统计，与日常视图形成差异——该差异由各自饼图的口径决定，每个视图内部自洽。
- Q: 合计视图下，某周期该分类的日常明细与大额明细合起来只显示前 3 条时，这 3 条按什么顺序取？ → A: **日常在前、大额在后**，两组内部各自沿用该组既有的展示顺序，跨组不混排（不按金额、也不按日期交错）。这与 FR-009「分日常与大额两组」的结构一致，「前 3 条」正好是卡片内展开后列表的开头，不会产生认知落差。此答案同时消解了 Assumptions 中"沿用既有展示顺序"与 FR-009 分组结构之间的潜在冲突——合计卡片未筛选时本就没有明细列表，不存在可继承的统一顺序，故由本次明确约定。
- Q: 当筛选已生效、用户把报表切到「支出趋势」时，该视图既没有饼图也没有图例，用户该从哪里取消这个筛选？ → A: **吸顶筛选标签在两个报表视图下都常驻**。切到「支出趋势」后标签仍在、关闭控件仍可用，卡片继续按该分类筛选（维持在 FR-017 的"保留"之上）。理由是用户在趋势视图下同样想看着某分类的明细比对走势，而标签是唯一不依赖饼图的取消入口；让它常驻几乎零成本，并彻底消除"筛选取消不掉"的死状态。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 日常视图：按分类下钻各周期的支出 (Priority: P1)

用户打开「历史记录」页并停留在默认的**日常**视图。上方报表区展示「支出占比」饼图，按分类（购物、生活、工作、娱乐、大餐、杂项、其他）呈现所选年份/月份范围内的支出构成；下方是逐个记账周期的卡片列表，每张卡片当前以固定维度展示「个人消费」与「其他消费」两个金额。

用户想知道"这类花销具体是哪些、花在了哪几个周期"。用户点击饼图中「购物」扇区后，下方每张周期卡片在该周期既有的汇总行下方追加「购物」分类的展示：先给出该周期购物花销的小计，再逐条列出具体的支出记录（描述与金额），使用户无需离开本页即可看清每笔钱花在哪。若某周期的条目超过 3 条，卡片只列前 3 条并给出「查看全部 N 条」控件，点击后在该卡片内原地展开为全部条目。

卡片第一行的主金额（该周期总支出）保持不变，为分类金额提供总量参照。用户再次点击「购物」扇区，卡片恢复为原本的固定维度展示。

**Why this priority**: 「日常」是历史记录页的默认与最高频视图，绝大多数账目集中在此。该视图的报表分类与卡片现有展示维度（个人/其他）此前并不对应——「其他消费」虽有金额却不在饼图内，用户既无法从卡片看出分类构成，也无法下钻其他消费。本功能补齐「其他」扇区后，饼图分类与卡片维度完全对齐，单独交付即可解决主要问题。

**Independent Test**: 进入历史记录页停留在日常视图，点击饼图中任意占比大于 0 的分类扇区，确认下方每张周期卡片都改为显示该分类的小计与逐条支出记录；再次点击同一扇区，确认卡片恢复原样。全程无需其他两个视图即可验证。

**Acceptance Scenarios**:

1. **Given** 日常视图的饼图展示了「购物 / 生活 / 工作 / 娱乐 / 大餐 / 杂项 / 其他」中的多个分类，**When** 用户点击「购物」扇区，**Then** 下方每张周期卡片在该周期既有的汇总行下方追加显示「购物」分类的金额小计，并逐条列出该分类下的支出记录（每条含描述与金额）；卡片第一行的总支出与第二行的「个人消费 / 其他消费」汇总列均保持原样。
2. **Given** 某周期在「购物」分类下有 6 条支出记录，**When** 用户点击「购物」扇区，**Then** 该卡片只列出前 3 条，并显示「查看全部 6 条」控件；点击该控件后，卡片在原位展开为 6 条，全程不离开本页，且展开后可以收起回到 3 条。
3. **Given** 已点击「购物」扇区且卡片处于筛选状态，**When** 用户再次点击「购物」扇区，**Then** 追加的分类小计与明细全部消失，卡片恢复为仅保留汇总行的原样，汇总行内容自始至终未发生改变。
4. **Given** 已点击「购物」扇区，**When** 用户改为点击「生活」扇区，**Then** 卡片直接切换为「生活」分类的小计与明细，且同一时刻只有一个分类生效。
5. **Given** 某个周期在「购物」分类上没有支出，**When** 用户点击「购物」扇区，**Then** 该周期卡片仍然显示，其小计显示为零且不列出任何明细条目，卡片不会从列表中消失。
6. **Given** 某分类在饼图上的占比很小、扇区窄到难以点中，**When** 用户点击右侧图例中该分类所在的行，**Then** 效果与点击扇区完全一致，卡片切换到该分类的展示；再次点击该图例行则取消筛选。
7. **Given** 日常视图存在若干「其他消费」记录，且它们录入时各自选择了「购物」「生活」等不同子类，**When** 用户点击「其他」扇区，**Then** 该扇区金额为这些记录的总和（不按子类拆分），下方每张周期卡片逐条列出该周期全部其他消费记录，不受录入时所选子类影响。

### User Story 2 - 大额视图：按分类下钻大额支出 (Priority: P2)

用户切换到**大额**视图。该视图的报表饼图按大额支出的分类构成呈现占比，下方是各周期的大额记录卡片。用户点击饼图中某一分类，下方各周期卡片随即筛选出该分类的大额支出，逐条列出具体记录，便于定位是哪几笔、哪几个周期产生了这类开销。再次点击同一分类即取消筛选。

**Why this priority**: 大额记录与日常支出的分类体系相互独立，是独立的用户旅程与独立的验证路径。日常视图交付后，用户会自然地期待大额视图具有同样的下钻能力，但它不阻塞日常视图的价值交付。

**Independent Test**: 切换到大额视图，点击饼图中任意分类扇区，确认下方每张周期卡片显示该分类大额支出的小计与逐条记录；再次点击确认筛选取消。

**Acceptance Scenarios**:

1. **Given** 大额视图的饼图展示了大额支出的分类占比，**When** 用户点击某一分类扇区，**Then** 下方每张周期卡片显示该周期该分类大额支出的金额小计，并逐条列出对应的大额支出记录。
2. **Given** 某周期在该分类下有超过 3 条大额支出记录，**When** 用户选中该分类，**Then** 卡片只列前 3 条并显示「查看全部 N 条」控件；点击后在该卡片内原地展开全部条目，不跳转到该周期的大额记录页。
3. **Given** 已在大额视图选中某分类，**When** 用户再次点击该分类扇区，**Then** 卡片恢复为筛选前的完整展示（「大额追加」「个人支出」「其他支出」三组按原样回归）。
4. **Given** 大额视图中存在没有该分类大额支出的周期，**When** 用户选中该分类，**Then** 该周期卡片仍然保留，小计显示为零且无明细条目。

---

### User Story 3 - 合计视图：同时下钻日常与大额两部分 (Priority: P3)

用户切换到**合计**视图，该视图的报表饼图合并了日常与大额两部分的分类构成，下方卡片同时展示每个周期的「日常消费」与「大额记录」两个金额。用户点击饼图中某一分类后，卡片在该汇总行下方针对该分类把记录分成日常与大额两组，分别给出小计与逐条明细，使用户理解该分类的开销中有多少来自日常记账、多少来自大额记录。若两组条目合计超过 3 条，同样只列前 3 条并提供「查看全部 N 条」控件。再次点击同一分类即取消筛选。

**Why this priority**: 合计视图依赖日常与大额两套分类体系的合并语义，实现与验证的复杂度最高。前两个视图各自独立可用，合计视图是在此之上的整合增强。

**Independent Test**: 切换到合计视图，点击饼图中同时存在于日常与大额两边的分类（如「购物」），确认卡片分别给出该分类的日常部分与大额部分的小计与明细；仅存在于单边的分类也能正常筛选。再次点击确认筛选取消。

**Acceptance Scenarios**:

1. **Given** 合计视图的饼图合并了日常与大额分类，**When** 用户点击「购物」扇区，**Then** 下方每张周期卡片在该周期既有的「日常消费 / 大额记录」汇总行下方，把该周期的「购物」记录分为日常与大额两部分，各自给出金额小计与逐条明细；汇总行两列的原值保持不变。
2. **Given** 某分类（如「大餐」）仅在大额记录中存在、日常账目中没有，**When** 用户点击该分类，**Then** 卡片仍正常筛选，日常部分小计显示为零且无条目，大额部分正常列出。
3. **Given** 某周期在「购物」分类下日常有 2 条、大额有 3 条记录，**When** 用户选中「购物」，**Then** 卡片共列出 3 条——先取日常组的 2 条、再取大额组的第 1 条，并显示「查看全部 5 条」控件；点击后在该卡片内展开，日常与大额两部分共 5 条全部可见。
4. **Given** 已选中某分类，**When** 用户再次点击同一扇区，**Then** 追加的分类小计与明细全部消失，卡片恢复为仅显示「日常消费 / 大额记录」汇总行的原样。

### Edge Cases

- **周期在该分类下无支出**：卡片保留在列表中，小计显示为零且不渲染任何明细条目——与卡片现有的"无支出显示零"行为保持一致，避免列表因筛选而剧烈抖动。
- **明细条目超过 3 条**：卡片只列出前 3 条，超出部分经「查看全部 N 条」在该卡片内原地展开查看，全程不离开本页。展开是有意识地由用户触发的动作，因此"展开后卡片变高"是预期行为而非缺陷；未展开时卡片高度恒定。
- **展开状态的存续**：展开属于页面临时状态。取消筛选、切换分类、切换报表视图或调整范围条件时，所有卡片的展开状态 MUST 一并重置为折叠；离开并重新进入历史记录页后 MUST 处于折叠状态。否则会出现"筛走的分类卡片仍是展开态"这类无处解释的残留。
- **筛选状态下向下滚动列表**：筛选标签吸顶常驻，用户在列表任意位置都能看到当前筛选的分类并直接关闭，无需回滚到顶部；标签不遮挡卡片内容。
- **「杂项」无逐条记录**：日常与合计视图中「杂项」的金额完全由倒推残值构成（本金减去各项支出与余额），不存在对应的支出记录。筛选该分类时，卡片只显示小计并附一行说明，标明该金额来自未逐条记录的部分；不渲染明细条目，也不显示「查看全部」控件。合计视图下该小计落在「日常」那一侧，「大额」一侧显示为零——因为残值只在日常侧产生。这是本功能中唯一"小计有金额、明细必然为空"的分类。
- **「其他」与「杂项」的差别**：二者在卡片上的呈现不同。「其他」扇区有真实的逐条支出记录，筛选后与其他分类一样列出明细条目；「杂项」没有底层记录，按 FR-022 只显示小计与说明。不要因为两者都是"兜底口径"就套用同一种呈现。
- **汇总列与筛选明细口径不同**：筛选状态下，汇总行仍按未筛选口径显示——「个人消费」是该周期全部非其他消费、「日常消费」是该周期日常侧的全部分类。因此会出现汇总列显示为零、其下方明细却有金额的情况（如「个人消费 ¥0」下方列出「购物 ¥320」）。这是 FR-013「保留汇总信息」的直接结果，是设计而非数据错误，不应作为缺陷修复。
- **大额卡片的净额不受筛选影响**：大额卡片第一行的数字是净额（大额追加合计减去大额支出合计），而筛选只作用于支出侧。因此筛选状态下净额仍按"追加与支出相抵"计算并原样显示，MUST NOT 改为"仅所选分类的支出金额"，否则同一位置在不同分类间会得到无法互相比较的数字。
- **筛选状态下净额缺少可见出处**：「大额追加」组在筛选时被替换掉，而第一行的净额仍按"追加合计减去支出合计"计算。因此筛选状态下净额里包含的那部分追加，在卡片上找不到对应的明细可查。这是 FR-008 与 FR-013 共同作用的结果，是设计而非缺陷；需要用第一行数字逐笔对账时应先取消筛选。
- **无描述的支出记录**：明细条目在缺少描述时以该记录所属分类名称占位，不显示空白。
- **筛选期间调整范围条件（年份、月份或阶段）**：三者适用同一条规则——已选中的分类保持不变，卡片按新范围重新计算该分类的小计与明细；若新范围内该分类完全没有任何金额，则筛选自动取消，卡片恢复固定展示。阶段是范围中最细的一级，切换阶段会使饼图的分类集合整体改变，但分类筛选的存续规则不变；且选中阶段后，卡片在筛选态下的统计口径随之收敛到该阶段（见 FR-016a），与饼图保持一致。
- **筛选期间切换报表视图**：报表可在「支出占比」与「支出趋势」之间切换，饼图仅在「支出占比」下存在。切到「支出趋势」时已选中的分类不被清除，切回「支出占比」后筛选仍然生效。该视图下扇区高亮与图例行高亮自然无处可显（饼图不存在），但吸顶筛选标签 MUST 照常渲染、其关闭控件 MUST 可用——否则用户会进入一个既看不到筛选来源、又找不到取消入口的死状态。切换报表视图 MUST NOT 派发取消筛选。
- **报表因无数据而不展示**：当所选范围内没有任何支出时，报表区整体不渲染，饼图不存在，因而不存在筛选入口。
- **结余项**：结余（本金减去支出的差额）不参与饼图渲染，因此不构成可点击的筛选入口；饼图中不存在与「杂项」同名的第二个扇区。
- **点中扇区之外**：视为取消当前筛选，与再次点击同一分类的结果一致。
- **占比极小的分类**：占比低于 5% 的分类不显示徽标，扇区只是一道窄弧，难以点中；图例行提供了尺寸充足的等价入口，保证这类分类仍然可被筛选，不会出现"看得见但选不中"的分类。
- **视图之间切换**：切换视图即清空筛选，切回后一律回到未筛选状态。筛选不跨视图传递，因此不会出现"所选分类在目标视图不存在、卡片集体显示零"的情况。
- **大额视图的"筛选后反而更短"**：大额卡片在未筛选时全量逐条列出所有记录，筛选后按统一规则只列前 3 条。因此该视图中"筛选后的卡片比筛选前更短"是设计结果而非缺陷——筛选的目的是聚焦到某一分类，超出部分经「查看全部」在该卡片内原地展开查看。此项为已确认的取舍，不应作为缺陷修复。
- **卡片整体点击行为不变**：筛选状态下点击卡片主体仍进入该卡片原本的跳转落点（日常与合计为周期详情页，大额为大额记录页），与未筛选时一致；明细条目本身不单独响应点击，「查看全部 / 收起」控件只切换展开状态、不触发跳转。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 报表的「支出占比」饼图 MUST 支持点击分类扇区，且 MUST 支持点击图例中对应的分类行；两种入口 MUST 等价，均将所点击的分类作为当前筛选条件。
- **FR-001a**: 日常视图的「支出占比」饼图 MUST 包含「其他」扇区，其金额为该周期全部「其他消费」记录的合计，MUST NOT 因这些记录带有自定义子类而拆入其他扇区。补上该扇区后，饼图 MUST 覆盖该周期的全部支出类型，各扇区金额之和 MUST 等于该周期总支出（倒推残值为负的周期除外，该情形见 Assumptions）。
- **FR-001b**: 大额视图与合计视图的饼图 MUST 同样将其他消费整体归入「其他」扇区，MUST NOT 按其子类并入子类同名的普通分类。三个视图对同一笔支出的分类归属 MUST 保持一致。
- **FR-002**: 系统 MUST 在选中某分类后（无论经由扇区还是图例行），将下方周期卡片列表的支出明细区域切换为该分类的支出展示。
- **FR-003**: 系统 MUST 在再次点击当前已选中的分类（无论扇区还是图例行）时取消筛选，使卡片恢复为筛选前的固定维度展示。
- **FR-004**: 系统 MUST 保证同一时刻至多只有一个分类筛选生效；点击另一分类 MUST 直接替换当前筛选。
- **FR-005**: 系统 MUST 在点击扇区与图例之外的空白区域时取消当前筛选。
- **FR-006**: 系统 MUST 在被选中的饼图扇区上给出视觉高亮；图例中对应分类所在行 MUST 同步高亮，两个入口的选中态 MUST 保持一致。其余扇区与图例行 MUST 保持未选中时的外观，MUST NOT 整体淡化。
- **FR-006a**: 系统 MUST 在列表滚动时保持一条筛选标签吸顶常驻于可视区域顶部；标签 MUST 显示当前筛选的分类名。该标签 MUST 在两个报表视图（「支出占比」与「支出趋势」）下同等渲染，MUST NOT 因切换到「支出趋势」而消失——该视图没有饼图与图例，标签是它唯一的取消入口。
- **FR-007**: 日常视图下，卡片 MUST 在该周期既有的汇总行下方显示所选分类的金额小计，并逐条列出该分类下的支出记录，每条含描述与金额。
- **FR-008**: 大额视图下，卡片 MUST 将既有的明细区域整体切换为所选分类的展示：给出该分类的金额小计，并逐条列出对应的大额支出记录。未筛选时可见的全量明细——包括「个人支出」「其他支出」两组，以及不属于支出、没有分类归属的「大额追加」组——在筛选状态下 MUST 全部被替换，MUST NOT 与筛选结果叠加显示。
- **FR-009**: 合计视图下，卡片 MUST 在该周期既有的汇总行下方，将所选分类的记录按日常与大额分为两部分，分别给出金额小计与逐条明细。
- **FR-010**: 当某周期在所选分类下没有任何支出时，系统 MUST 保留该周期卡片并显示零小计，MUST NOT 将其从列表中移除，也 MUST NOT 渲染空的明细区域。
- **FR-011**: 当所选分类在某周期下的明细条目超过 3 条时，系统 MUST 只展示前 3 条，并显示带有该分类条目总数的「查看全部 N 条」控件。点击该控件 MUST 在该卡片内原地展开、列出该分类在该周期下的全部条目，MUST NOT 跳转到任何其他页面，也 MUST NOT 以弹窗或浮层呈现。该规则 MUST 对日常、大额、合计三个视图同等适用，无论该视图未筛选时的明细是否已经全量展示。合计视图下，这「前 3 条」MUST 先取日常组、再取大额组，MUST NOT 跨组按金额或日期混排——两组各自沿用其既有的展示顺序。
- **FR-012**: 展开后 MUST 提供明确的收起路径，使用户可以恢复为只显示前 3 条的状态。展开与收起 MUST 只影响被操作的那一张卡片，MUST NOT 连带展开或收起其他卡片；系统 MUST 允许同时展开多张卡片。卡片主体的点击跳转落点 MUST 保持不变——日常与合计视图为该周期的详情页，大额视图为该周期的大额记录页；展开控件 MUST NOT 触发卡片主体的跳转。
- **FR-013**: 筛选生效时，卡片既有的汇总信息 MUST 全部保留在筛选结果上方，MUST NOT 被替换、移除或改写口径：日常与合计卡片的第一行保持该周期总支出，第二行保持「个人消费 / 其他消费」与「日常消费 / 大额记录」两列的原值；大额卡片的第一行保持其既有的净额口径（大额追加合计减去大额支出合计）。所选分类的小计与明细 MUST 追加在这些汇总信息下方。
- **FR-014**: 系统 MUST NOT 因筛选而修改任何账目数据；筛选仅为展示层的临时状态。
- **FR-015**: 筛选状态 MUST NOT 在退出历史记录页后保留——返回上级页面、切到其他模块或重新进入本页时，MUST 处于未筛选状态、吸顶筛选标签一并消失。从卡片主体进入该周期的详情页或大额记录页后再返回，属于同一次页面停留，筛选 MUST 保持生效。
- **FR-016**: 当用户调整范围筛选条件（年份、月份或阶段）后，已选中的分类 MUST 保持；若新范围内该分类无任何金额，筛选 MUST 自动取消。三类范围变更 MUST 适用同一条规则。
- **FR-016a**: 当「阶段」被选中且某分类筛选生效时，卡片 MUST 只统计属于所选阶段的支出——分类小计与逐条明细的口径 MUST 与饼图口径一致，MUST NOT 把该周期其他阶段的支出计入小计或列入明细。未筛选时卡片 MUST 保持既有行为（仍按整个周期展示），本条 MUST NOT 改变未筛选时卡片的任何数字。大额与合计视图的饼图不受阶段选择影响，故这两个视图的筛选口径 MUST 保持为整个周期，MUST NOT 因本条而改为按阶段统计。
- **FR-017**: 报表从「支出占比」切换到「支出趋势」时，系统 MUST 保留当前筛选；切回「支出占比」后筛选继续生效。该视图下吸顶筛选标签 MUST 照常渲染且其关闭控件 MUST 可用（见 FR-006a），使筛选在无饼图的情况下依然能够取消。
- **FR-018**: 用户切换到另一个**记账视图**（指日常 / 大额 / 合计这三选一的分段按钮，MUST NOT 与「报表视图」即支出占比 / 支出趋势混淆）时，系统 MUST 清空当前筛选；切回原视图后 MUST 处于未筛选状态，吸顶筛选标签一并消失。
- **FR-019**: 饼图 MUST NOT 渲染结余项，结余 MUST NOT 作为可筛选的分类。
- **FR-020**: 吸顶筛选标签 MUST 提供关闭控件；点击该控件取消当前筛选，其效果与再次点击同一分类完全一致。
- **FR-021**: 未处于筛选状态时，系统 MUST NOT 渲染吸顶筛选标签。
- **FR-022**: 当所选分类在某周期的小计大于零、却没有任何可逐条列出的支出记录时（「杂项」即此种情形：其金额为倒推残值，不存在对应的支出记录），卡片 MUST 只显示小计并附一行说明，标明该金额来自未逐条记录的部分；MUST NOT 渲染空白明细区域，也 MUST NOT 显示「查看全部」控件。该规则 MUST 同时适用于日常与合计两个视图——两者的饼图都存在「杂项」扇区；大额视图不出现此种情形。
- **FR-023**: 筛选状态下的每行明细 MUST 只显示该条支出的描述与金额，MUST NOT 显示分类标签或子类标签。「其他」分类下的明细行尤其 MUST NOT 显示其录入时所选的子类名——子类名与普通分类同名时，用户将无法分辨这笔钱究竟属于哪一边。该规则对三个视图同等适用。本条约束的是与描述并列的独立标签元素（分类图标、分类名、子类名等）；当描述为空而以分类名占位时（见 Edge Cases「无描述的支出记录」），该占位文本 MUST NOT 被视为违反本条。

### Key Entities

- **支出分类（Category）**：账目归属的类别，如「购物」「生活」「工作」「娱乐」「大餐」「杂项」「其他」，是饼图扇区与筛选条件的取值来源。
- **支出记录（Expense Record）**：一条具体的支出，含描述与金额，归属某个分类与某个周期，是筛选后逐条明细的展示单位。
- **记账周期（Period）**：一段起止日期，是下方卡片的单位，也是分类小计与明细列表的统计主体。
- **筛选状态（Filter State）**：当前选中的分类，或"未筛选"。属于页面级的临时展示状态，不持久化。
- **展开状态（Expanded State）**：某一张卡片是否已展开显示该分类的全部条目。以卡片为单位、相互独立，同样属于页面临时状态，取消筛选或离开页面即重置。
- **报表汇总数据**：所选时间范围内的分类金额合计，决定饼图各扇区的占比，也是筛选小计的对照基准。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 用户在报表饼图上点击任一分类后，无需进入任何子页面或二次确认，一次交互内即可看到下方全部周期卡片切换为该分类的小计与明细。
- **SC-002**: 用户取消筛选只需一次交互即可完成——无论当前滚动到列表的哪个位置，都可通过吸顶筛选标签直接关闭，或点击同一分类（扇区或图例行）、点击扇区与图例之外的空白。在「支出趋势」视图下饼图与图例都不存在，此时 MUST 仍可通过吸顶筛选标签关闭，不存在任何"筛选生效但无入口可取消"的状态。
- **SC-003**: 筛选某分类后，下方全部周期卡片在该分类下的小计之和，与报表图例中该分类显示的合计金额一致。该一致性 MUST 在年份、月份、阶段三种范围条件下同等成立——卡片与饼图在任何时候都采用同一个统计范围。
- **SC-004**: 未展开时，单张卡片的高度只由固定内容决定（汇总行 + 分类小计 + 至多 3 条明细），不随该分类的条目总数增长。只有用户主动展开某张卡片后，该卡片的高度才随条目数增长，且其他卡片的高度不受影响。
- **SC-005**: 三个视图各自独立可用——任一视图的筛选功能可单独交付并单独验证，不依赖另外两个视图是否已实现。
- **SC-006**: 筛选操作不产生任何数据写入；退出并重新进入历史记录页后，页面回到未筛选状态。
- **SC-007**: 在任一视图中筛选之后切换视图，三个视图都处于未筛选状态，不存在隐式残留的筛选。
- **SC-008**: 饼图上出现的每一个分类，无论占比多小，都存在一个尺寸充足的筛选入口，不存在"看得见但选不中"的分类。

## Assumptions

- **筛选结果的呈现方式**：需求中的「支出明细」与卡片代码中既有的"支出明细"区域命名一致，故判定筛选作用于卡片已有的支出明细区域——在其中给出分类小计并逐条列出记录，而非新增独立的支出明细页面。
- **明细条目的排序**：日常与大额视图的卡片内明细沿用该周期该分类支出既有的展示顺序，取前 3 条，使卡片中看到的前 3 条与在卡片内展开后的前 3 条顺序一致，不会产生认知落差。合计视图的卡片未筛选时没有明细列表、不存在可继承的统一顺序，故约定**先日常组、再大额组**，两组各自沿用其既有顺序，跨组不混排。
- **「查看全部」的呈现方式**：不跳转、不弹窗，在卡片内原地展开。这是本次唯一新增的交互控件，只服务于"条目超过 3 条"这一种情形；卡片主体原有的跳转行为不受影响。由于展开后条目全部可见，此处不再存在"卡片内显示 N 条、落点页却显示更多条"的口径落差。
- **零金额周期保留**：卡片现有代码在周期无支出时已显示"¥0"而非隐藏卡片，筛选沿用同一行为，以保证列表稳定、便于用户对照。
- **筛选状态为临时状态**：需求未提及记忆筛选，且项目定位为本地个人工具，故判定筛选不跨页面保留、不写入设置。
- **筛选在"进子页面再返回"时保留**：进入子页面再返回并不销毁本页状态，筛选自然保持生效。此处刻意不做清空——用户从卡片点进去看一眼再返回就要重新点一次饼图，属于无谓的操作成本；FR-015 约束的是"退出本页"，而非"短暂离开当前视图"。
- **展开状态在筛选结果重算时重置**：切换分类、调整范围条件、切换报表视图都会使卡片内容整体重算，此时所有卡片的展开状态一并收起到前 3 条，避免出现"新分类的卡片仍停留在展开态"这类与用户上一次操作无关的残留。
- **结余不参与饼图**：结余（本金减支出的差额）在饼图构造时即被排除，不出现在图例中，因此不构成筛选入口。本次不改变这一既有行为。
- **「杂项」是设计上的倒推残值**：它不是漏建的分类，而是"本金中未被逐条记录的部分"，其数值来自本金减去各项支出与余额。本次不改变这一口径，只为其筛选结果补充说明文案。
- **报表两种视图的关系**：饼图仅存在于「支出占比」视图，因此筛选入口也只在该视图出现；「支出趋势」视图不承担筛选职责。
- **分类体系以页面现有数据为准**：筛选使用的分类集合以饼图实际渲染出的分类为准。本次不新增、不改写分类定义——日常饼图新增的「其他」扇区用的仍是既有分类，大额与合计的「其他」扇区金额口径按 FR-001b 统一调整。
- **其他消费的归类语义**：一笔其他消费只归属「其他」这一个分类，其录入时选择的子类不参与饼图分类、也不影响它在筛选结果中的归属。筛选「其他」时，该周期全部其他消费记录都应在明细中列出。该子类同样不显示在明细行上——它只存在于数据库，三个视图的明细行都不呈现分类标签。
- **饼图分类归属的三处变更**：(1) 日常饼图由"部分支出类型"改为覆盖全部支出类型，各扇区占比随之整体变化（分母变大）；(2) 其他消费不再按其子类拆入同名普通分类，而整体归入「其他」；(3) 报表标题旁的总金额取自饼图各扇区之和，因此日常视图这个数字会随「其他」扇区的补入而变大，并从此与日常卡片第一行的周期总支出对齐（此前二者不相等）。三处都是本次有意引入的既有图表行为变更，MUST 在发布说明中提及。
- **「杂项」为负时不进饼图**：饼图构造时只在倒推残值为正时计入「杂项」，残值为负的周期被直接忽略；而卡片第一行的周期总支出仍按实际数值计算（可能已包含负残值）。因此在这类周期上，筛选小计之和与图例合计可能无法严格对齐（SC-003）。本次不改变饼图对负值的处理——饼图本身无法表达负扇区。
- **三个视图对「阶段」的既有响应并不一致**：选中阶段时，只有日常视图的饼图切换为阶段维度数据，大额与合计视图的饼图完全忽略阶段选择。这是既有行为，本次不改变。卡片筛选的口径按各自饼图对齐，因此**日常视图筛选后按所选阶段统计，而大额与合计视图筛选后仍按整个周期统计**。这是 FR-016a 的直接结果，不应被当作"三个视图行为不一致"的缺陷修复——若日后要统一，应统一在饼图侧（让三个视图的饼图都响应阶段），而不是让卡片去背离自己上方那张图。
- **目标用户与平台**：面向已在使用本应用记录账目的个人用户，功能在 Android 与 Windows 上行为一致。
