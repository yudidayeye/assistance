# Quickstart 验证指南：历史记录报表饼图点击联动周期卡片筛选

**Feature**: `001-report-pie-filter` | **Date**: 2026-09-20

本文件是**跑起来验证**的指南，不含实现代码。设计细节见 [plan.md](./plan.md) 与 [contracts/ui-contract.md](./contracts/ui-contract.md)。

---

## 0. 前置条件

- Flutter stable，`pubspec.yaml` 无需改动（本次**不新增依赖**）
- 已验证的 Windows 桌面运行环境（`flutter run -d windows`）
- 一份**含多个记账周期、且分类分布有差异**的本地数据。推荐的构造要点：
  - 至少 1 个周期在某分类下有 **> 3 条**记录（验证「查看全部」）
  - 至少 1 个周期在某分类下**没有**任何记录（验证零小计周期保留）
  - 至少 1 笔**其他消费**，且录入时子类选了「购物」（验证 FR-001b 的归类）
  - 至少 1 个周期有**多个阶段**（验证 FR-016a 的阶段口径）
  - 若某周期倒推残值为正，即可验证「杂项」

## 4. 端到端验证场景

### S1 — 日常视图下钻（US1 / FR-001 / FR-002 / FR-007 / FR-013）

1. 点击饼图中「购物」扇区。
2. **预期**：下方每张周期卡片在既有汇总行下方追加「购物」小计与逐条明细；第一行总支出与第二行「个人消费 / 其他消费」**原样不变**；被点扇区高亮；图例中「购物」行同步高亮；列表顶部出现吸顶筛选标签，显示「购物」。

### S2 — 取消筛选（FR-003 / FR-005 / FR-020 / SC-002）

分别验证三条取消路径，结果必须一致：
- 再次点击「购物」扇区
- 点击图例中「购物」行
- 点击吸顶标签的关闭控件

**预期**：分类小计与明细全部消失，卡片恢复原样；扇区与图例高亮消失；标签消失。

### S3 — 下滚后取消（FR-006a / SC-002）

选中分类后把列表向下滚动若干屏。

**预期**：标签仍吸顶可见；点击其关闭控件能取消筛选，**无需回到顶部**。滚动过程中标签底色不透明，卡片内容不穿透造成误读。

### S4 — 前 3 条与原地展开（FR-011 / FR-012 / SC-004）

选中一个在该周期有 6 条记录的分类。

**预期**：只列 3 条 + 「查看全部 6 条」；点击后**在原卡片内**展开为 6 条，**不跳页、不弹窗**；再点可收起。展开一张卡片时，**其他卡片高度不受影响**；允许同时展开多张。点击卡片主体（非控件区域）仍进入该周期详情页。

### S5 — 零小计周期保留（FR-010）

选中一个在部分周期没有记录的分类。

**预期**：这些周期卡片仍在列表中，小计显示「¥0」，且**不出现空白明细区**。

### S6 — 小占比分类经图例筛选（FR-001 / SC-008）

选中占比 < 5% 的分类（扇区极窄、无徽标）。

**预期**：点击图例行即可筛选，效果与点扇区完全一致。

### S7 — 「其他」的归类（FR-001b / FR-023）

点击「其他」扇区。数据中有一笔子类为「购物」的其他消费。

**预期**：该笔**出现在「其他」的明细里**，且**不出现在「购物」的明细里**。明细行只显示描述与金额——**不出现任何「购物」之类的分类或子类标签**。

### S8 — 「杂项」（FR-022）

点击「杂项」扇区（仅日常与合计视图有此扇区）。

**预期**：卡片只显示小计 + 一行「来自未逐条记录的部分」的说明；**无明细条目、无「查看全部」**。切到大额视图确认**没有**「杂项」扇区。

### S9 — 阶段口径（FR-016a）

在筛选栏选中一个阶段，然后点击某分类（如「购物」）。

**预期（日常视图）**：卡片小计与明细**只含该阶段的记录**；把各卡片小计相加，**等于图例中该分类的金额**（SC-003）。
切到**合计**视图重复一次：卡片小计按**整个周期**统计（该视图饼图不响应阶段），同样与图例一致。

### S10 — 范围变更（FR-016）

选中分类后，依次调整年份、月份、阶段。

**预期**：筛选保持并按新范围重算；若新范围内该分类完全没有金额，筛选自动取消、卡片恢复固定展示。

### S11 — 报表视图切换（FR-017 / FR-006a）

选中分类后，把报表从「支出占比」切到「支出趋势」。

**预期**：筛选**保留**；扇区与图例高亮自然消失（饼图不在了），但**吸顶筛选标签仍然渲染**；点击标签的关闭控件能取消筛选，卡片随之恢复原样。切回「支出占比」时若尚未取消，筛选状态与高亮应完整重现。

> 这一条专门验证"死状态"是否被堵住：该视图下点不了扇区、点不了图例、也没有可点空白，标签若不渲染就再也取消不掉。

### S12 — 视图切换清空（FR-018 / SC-007）

选中分类后切到大额视图。

**预期**：筛选**已清空**、标签消失。三个视图（日常 / 大额 / 合计）逐一验证；**左右滑动**切换也必须清空，不能只验分段按钮。

### S13 — 大额视图（US2 / FR-008）

选中某分类。**预期**：未筛选时可见的「大额追加」「个人支出」「其他支出」三组**全部被替换**，仅剩该分类小计与明细；第一行净额数字**保持不变**（不改为「仅所选分类的支出金额」）。

### S14 — 合计视图（US3 / FR-009）

选中同时存在于两边的分类（如「购物」）。**预期**：小计与明细分**日常 / 大额两组**；某周期日常 2 条 + 大额 3 条时，先显示 **3 条**（日常 2 + 大额 1）+ 「查看全部 5 条」，展开后 5 条全可见。

### S15 — 状态不持久化（FR-014 / FR-015 / SC-006）

选中分类后，从卡片进入周期详情页再返回 → 筛选**保持**。
返回上级页面（或切到别的模块）再重新进入历史记录页 → **未筛选**、标签消失。

## 5. 常见坑（实施时对照）

| 现象 | 多半是 |
| :--- | :--- |
| 改年份后筛选跳到了另一个分类 | 筛选键用了扇区下标（数组按金额排序，变了）—— 见 research R1 |
| 筛选「购物」时混进了其他消费 | 归类时先调了 `mapCategoryForDisplay` —— 见 research R5 |
| 明细行冒出了「购物」标签 | 误用了 `buildExpenseItem` 而非 `_buildDetailRow` —— 见 research R7 |
| 滑动切换视图后筛选还留着 | 清空只挂在了 `onSelectionChanged`，漏了 `_tabController` 监听 —— 见 research R9 |
| 卡片小计相加 ≠ 图例金额（日常视图选中阶段时） | 卡片没按阶段收敛 —— 见 FR-016a |
| 点「查看全部」跳走了页面 | 展开控件未阻止冒泡到卡片主体的跳转 —— 见 FR-012 |
