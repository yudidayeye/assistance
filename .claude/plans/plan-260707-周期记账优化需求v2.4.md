### 需求1：阶段卡片展开/收起按钮移至卡片下方

#### 现状
- `StageCard` 头部（`GestureDetector` 包裹整行）点击触发 `_toggleExpand()`
- 头部右侧有展开/收起箭头图标（`AnimatedRotation`）
- 卡片底部无操作栏（v2.3 已删除 `_buildBottomActions`）

#### 方案
- **移除** 头部的 `GestureDetector` 点击展开/收起功能
- 头部保留信息展示 + 编辑按钮，纯展示用途
- 卡片底部新增一个独立的「展开明细」/「收起明细」按钮区域
- 按钮样式：柔和背景色 + 圆角，左侧图标 + 文字
- 展开状态切换逻辑保持不变（`_toggleExpand` 方法保留，仅改变触发方式）

#### 改动清单

|------|------|

### 需求2：阶段编辑页内嵌添加支出/追加表单（无弹窗）

#### 现状
- 阶段编辑页已有「+ 添加追加」按钮，点击后弹出 `showModalBottomSheet` 底部弹窗（`_showAddAdditionDialog`）
- 支出区域只有「已有支出」列表 + 「+ 添加到列表」按钮（批量记账表单）
- `AddExpensePage` 是独立页面，目前为 stub（显示"开发中"）

#### 方案
**追加记录：**
- 移除 `_showAddAdditionDialog()` 方法及其底部弹窗
- 在追加卡片中，点击「+ 添加追加」后，在卡片内部下方**展开内嵌表单**
- 表单包含：追加原因输入框 + 金额输入 + 确认按钮
- 添加成功后：追加记录插入列表顶部，表单清空，**保持展开状态**便于连续添加
- 提供「收起」按钮关闭表单

**支出记录：**
- 在「已有支出」列表下方新增「+ 添加支出」文字按钮
- 点击后展开内嵌表单：分类选择（购物/其他）+ 金额输入 + 描述输入 + 确认按钮
- 添加成功后：支出记录插入列表，表单清空，保持展开状态
- 注意：与现有的批量记账表单（`_buildBatchExpenseSection`）功能重叠，需合并或区分职责
  - **建议**：保留批量记账表单作为"批量添加"区域，新增的「+ 添加支出」作为单条快速添加
  - 或者：将批量记账表单改造为单条添加表单，移除"待保存列表"概念
  - **最终方案**：保留现有批量记账表单不变，在「已有支出」区域新增单条添加入口

**`AddExpensePage` 处理：**
- 当前为 stub 页面（显示"记一笔（开发中）"），路由 `add-expense` 仍在模块中注册
- 评估：**保留路由但不再从阶段编辑页跳转**，后续可扩展为独立记一笔页面
- 或者：**删除路由注册**，避免用户误入空白页
  - **建议**：先删除路由注册（注释掉），后续需要时恢复

### 需求3：阶段日期支持设置「当前日期」

#### 现状
- `StageRecord` 仅有 `startDate` / `endDate`
- `StageRecord.totalDays` = endDate - startDate + 1
- `getStageCalculations` 中 `livingDailyAvg = livingTotal / totalDays`
- 阶段编辑页日期区域只有开始/结束日期两行

#### 方案

**数据模型：**
- `StageRecord` 新增 `currentDate` 字段（String?），默认 null
- 新增 `livingDays` getter：
  ```dart
  int get livingDays {
    final start = DateTime.parse(startDate);
    final end = DateTime.parse(endDate);
    final current = currentDate != null ? DateTime.parse(currentDate!) : end;
    final effective = current.isBefore(start) ? start : (current.isAfter(end) ? end : current);
    return effective.difference(start).inDays + 1;
  }
  ```

**数据库迁移：**
- 当前版本 7 → 升级到 8
- `_onUpgrade` 中增加 v7→v8：`ALTER TABLE mod_period_book_stages ADD COLUMN current_date TEXT`
- `_createV4Schema` 中建表语句同步增加 `current_date TEXT` 列
- 存量数据 `current_date` 为 NULL → `livingDays` 自动回退到 `endDate`，行为不变

**计算逻辑：**
- `getStageCalculations`：`totalDays` → `stage.livingDays`
- `getPeriodCalculations`：同理替换
- 注意：`StageCalculations` 模型中 `totalDays` 字段仍保留（表示日历天数），但生活费日均使用 `livingDays`

**UI：**
- 阶段编辑页日期区域新增第三行：「当前日期（用于计算日均）」
- 默认显示阶段 endDate
- 点击弹出 `showDatePicker`，`firstDate` = startDate，`lastDate` = endDate
- 选择后更新 `_stage.currentDate`

#### 改动清单
| 文件 | 改动 |
|------|------|
| `lib/modules/period_book/models/stage_record.dart` | 新增 `currentDate` 字段 + `livingDays` getter |
| `lib/core/storage/database_service.dart` | `_currentVersion` 改为 8；`_onUpgrade` 增加 v7→v8；`_createV4Schema` 增加列 |
| `lib/modules/period_book/services/period_book_service.dart` | `getStageCalculations` / `getPeriodCalculations` 中 `totalDays` → `livingDays` |
| `lib/modules/period_book/pages/stage_edit_page.dart` | 日期区域新增当前日期行 + 选择器 |

### 需求4：历史记录页面改为表格样式，支持删除

#### 现状
- `PeriodHistoryPage` 使用 `ListView.builder` + `Dismissible` 卡片列表
- 每行显示：日期范围、天数、总本金、余额
- 删除通过左滑触发确认弹窗

#### 方案

**表格样式：**
- 使用 `SingleChildScrollView` + `Table` 组件（或自定义 Row 列表模拟表格）
- 移动端适配：由于列较多，采用**固定表头 + 横向滚动**的表格布局
- 或者：精简为关键列（周期名称、日期、总支出、操作），点击行进入详情

**列定义：**
| 列 | 说明 |
|----|------|
| 周期 | 开始日期 ~ 结束日期 |
| 天数 | 周期总天数 |
| 总支出 | 购物 + 其他 |
| 总追加 | 追加总额 |
| 余额 | 最新阶段余额 |
| 操作 | 删除按钮 |

**删除按钮：**
- 每行右侧直接显示「删除」图标按钮（而非左滑触发）
- 点击后弹出确认弹窗（复用现有 `_showDeleteConfirmDialog`）
- 确认后调用 `_service.deletePeriod()` 删除周期及关联数据

**表头固定：**
- 使用 `StickyHeader` 或自定义实现
- 简单方案：`CustomScrollView` + `SliverPersistentHeader` 固定表头

#### 改动清单
| 文件 | 改动 |
|------|------|
| `lib/modules/period_book/pages/period_history_page.dart` | 重写为表格样式，删除按钮内嵌每行 |
| `lib/modules/period_book/services/period_book_service.dart` | 确认 `getAllPeriods` + `deletePeriod` 方法存在且可用（已存在） |

## 四、执行建议

1. **按需求顺序实现**：1 → 2 → 3 → 4（依赖关系：需求3的计算逻辑需先于需求4）
2. **每完成一个需求**：运行 `flutter analyze` 检查语法，必要时运行 `flutter test`
3. **数据库迁移**：升级版本号后需卸载重装应用验证（或使用旧版本数据库升级测试）
4. **UI 验证**：在 Android 模拟器/真机上验证展开/收起、表单展开、日期选择、表格滚动

---

## 五、风险与注意事项

1. **需求2的表单持久化**：内嵌表单在卡片内部，需确保 `StatefulWidget` 状态正确维护，避免页面滚动时表单状态丢失
2. **需求3的日期边界**：`currentDate` 需限制在 [startDate, endDate] 范围内，前端日期选择器需设置 `firstDate`/`lastDate`
3. **需求4的表格性能**：历史周期数量通常不多（<50），`Table` 性能无问题；若数据量大需考虑分页
4. **`add-expense` 路由删除**：确认无其他页面/入口跳转到该路由（当前仅 `period_book_module.dart` 中注册）
