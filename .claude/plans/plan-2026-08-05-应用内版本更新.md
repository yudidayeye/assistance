# 应用内版本更新（替换"前往更新"跳转）

## Context（背景）

当前设置页的版本更新流程：检查到新版本 → 弹窗展示更新内容 → 点「前往更新」→ `url_launcher` 外部浏览器打开 GitHub Release 页，用户需手动下载并安装 APK，体验割裂。

本次改造为**应用内更新**：弹窗展示更新内容 → 点「立即更新」→ 弹窗内显示下载进度条（百分比 + 已下载大小）→ 下载完成自动唤起系统安装器。并且**按设备 CPU 架构自动匹配对应 APK**（Release 产物为按架构分包的 APK，系统自动决定下载哪个版本）。iOS 无法安装 APK，降级为原有外链跳转。

## 已核实的关键事实

- **现有代码**：`lib/core/settings/update_service.dart`（`UpdateService` 单例：`checkForUpdate()` 请求 GitHub API、`openReleasePage()` 外链跳转、`UpdateInfo` 未含 assets）；`lib/core/settings/settings_page.dart`（`_buildVersionItem()` 477-556 行、`_showUpdateDialog()` 559-634 行）
- **GitHub Release 实际产物**（仓库 `yudidayeye/assistance`，已实时核实）：仅三个按架构分包的 APK，**无 universal 包**：
  - `app-arm64-v8a-release.apk`（~20MB）
  - `app-armeabi-v7a-release.apk`（~17MB）
  - `app-x86_64-release.apk`（~21MB）
  - 每个 asset 含 `name` / `browser_download_url` / `size`
- **已有依赖**：http、url_launcher、package_info_plus、path_provider、path
- **Android 现状**：Manifest 仅有 INTERNET 等三个权限，无 `REQUEST_INSTALL_PACKAGES`、无 FileProvider；但 `android/app/src/main/res/xml/file_paths.xml` **已存在**（含 `external-files-path path="."`，覆盖 `getExternalStorageDirectory()`）——当前是孤立资源，只需在 Manifest 补 provider 声明即可复用，无需新建
- **构建**：AGP Kotlin DSL、compileSdk 36、minSdk 21、applicationId `com.example.my_assistant`

## 依赖选型（4 个新依赖）

| 依赖 | 用途 | 选型理由 |
|---|---|---|
| `dio` ^5.x | 下载 + 进度回调 + 取消 | 内置 `download(onReceiveProgress)`、`CancelToken`、`DioExceptionType` 错误分类；比 http 手写流式下载少 3-4 倍代码 |
| `open_filex` ^4.x | 唤起系统安装器 | 活跃维护（install_plugin 已停滞 3 年不选）；`OpenFilex.open(path)` 一行，内部处理 FileProvider URI / ACTION_VIEW / MIME，返回 `OpenResult` 可判成败 |
| `permission_handler` ^13.x | `REQUEST_INSTALL_PACKAGES` 运行时权限检测/申请/引导去设置 | `Permission.requestInstallPackages` + `openAppSettings()` |
| `device_info_plus` | 读取 `supportedAbis` 判断设备架构 | 官方 plus 系列，与已有 package_info_plus 同族 |

> ⚠️ 实现规范（用户全局指令）：写每个依赖相关代码前，先用 Context7 查最新文档确认 API——重点复核 dio download/CancelToken、open_filex 的 FileProvider authority 约定（疑似 `${applicationId}.fileProvider`）、permission_handler 在 Android 11+ 的行为、device_info_plus `supportedAbis`。

## 实施步骤

### 步骤 1：新增依赖
`pubspec.yaml` 添加 dio / open_filex / permission_handler / device_info_plus，`flutter pub get`。
（不单独 commit，避免"加了没用"的中间态）

### 步骤 2：AndroidManifest 配置
`android/app/src/main/AndroidManifest.xml`：
1. `<application>` 外新增 `<uses-permission android:name="android.permission.REQUEST_INSTALL_PACKAGES" />`
2. `<application>` 内新增 FileProvider（复用已有 `@xml/file_paths`）：
```xml
<provider
    android:name="androidx.core.content.FileProvider"
    android:authorities="${applicationId}.fileProvider"
    android:exported="false"
    android:grantUriPermissions="true">
    <meta-data
        android:name="android.support.FILE_PROVIDER_PATHS"
        android:resource="@xml/file_paths" />
</provider>
```
3. 无需存储权限（APK 下载到应用私有目录，不受 scoped storage 限制）
4. `file_paths.xml` 与 `build.gradle.kts` 无需改动

✅ **commit ①**：`新增应用内更新所需 Android 权限与 FileProvider 配置`

### 步骤 3：改造 UpdateService（`lib/core/settings/update_service.dart`）

1. **模型**：新增 `ReleaseAsset { name, downloadUrl, size }`；`UpdateInfo` 增加 `assets` 字段（默认 `const []`）；`checkForUpdate()` 追加解析 `json['assets']`
2. **架构匹配**（纯函数 `selectAsset(assets, supportedAbis)`，便于单测）：
   - 按设备 `supportedAbis` 优先级顺序遍历（如 `['arm64-v8a', 'armeabi-v7a', 'armeabi']`），找文件名包含对应 ABI 的 `.apk`（长令牌优先匹配，防 `armeabi-v7a`/`armeabi` 前缀误配）
   - Fallback 链：精确 ABI → universal/无架构标识 apk（预留）→ 任意 apk → 返回 null（UI 降级跳浏览器）
3. **下载** `downloadApk({asset, version, onProgress, cancelToken}) → Future<String?>`：
   - 保存路径 `getExternalStorageDirectory()/update_v{version}_{abi}.apk`（已被 file_paths.xml 覆盖）
   - 已存在且大小 == asset.size 直接复用；下载前清理旧 `update_*.apk`
   - `receiveTimeout` 放宽（GitHub 波动大）；total ≤ 0 时回退 asset.size
   - 取消 → 删部分文件返回 null；网络失败自动重试 1-2 次（重新全量下载，本期不做断点续传）
   - 完成后校验 `File.length() == asset.size`，不符删文件抛错
4. **权限** `ensureInstallPermission()`：Android 8+ 走 permission_handler 检测/申请，返回 granted/denied/permanentlyDenied 三态；Android 7.x 无按应用开关，视为 granted 直接尝试安装（系统自行拦截）
5. **安装** `installApk(path)`：`OpenFilex.open(path)`，返回成败
6. **保留** `openReleasePage()` 作为降级入口

✅ **commit ②**：`更新服务支持按设备架构匹配 APK 并下载、唤起安装`

### 步骤 4：弹框改造 + 接入（新文件 + settings_page.dart）

新建 `lib/core/settings/update_dialog.dart`——独立 StatefulWidget（settings_page.dart 已很长，4 状态机 + CancelToken 生命周期用正式组件管理）。入参：`UpdateInfo`、`appTheme`、匹配到的 `asset`。

**状态机** `enum _UpdatePhase { confirm, downloading, installing, failed }`：

| 状态 | UI | 按钮 |
|---|---|---|
| confirm | 沿用现有「发现新版本」内容（版本对比 + releaseNotes 卡片），主按钮改为「立即更新」 | 稍后再说 / 立即更新(sage) + 底部小字链接「前往 GitHub 发布页」兜底 |
| downloading | 标题「正在下载更新包」；`ClipRRect(radiusMd)` + `LinearProgressIndicator(value, minHeight 8, sage)`；显示 `45%` + `9.3 MB / 20.6 MB`；`barrierDismissible: false` + `PopScope(canPop: false)` 防误触 | 取消下载(rose) → 取消后回 confirm 态 |
| installing | 下载完成自动触发安装；从系统安装器返回后保留入口防失联 | 立即安装 / 稍后 |
| failed | 按 DioExceptionType 映射错误文案（网络/存储不足/文件损坏） | 重试(sage) / 取消 + GitHub 链接兜底 |

**点击「立即更新」时序**：① 权限前置检查（在下载之前，避免下完 20MB 才发现没权限；被拒 → 解释弹窗 +「去设置」`openAppSettings()`）→ ② 建 CancelToken、进 downloading → ③ `onProgress` 节流（≥100ms 或 ≥1% 才 setState，防掉帧）→ ④ 成功 → 自动调 `installApk` 进 installing → ⑤ 失败进 failed。所有异步间隙 `if (!mounted) return`；弹框 dispose 即取消下载（不做后台下载）。

**样式规范**（必读 `docs/UI.md`）：沿用现有弹窗模式——`barrierColor: surfaceOverlay`、`backgroundColor: cream`、52x52 图标容器（sage 10% 透明底 + radiusMd）、`AppTypography.displayMd` 居中标题、TextButton actions、无阴影、更新场景主色用 sage。

**iOS / 无匹配 asset 降级**：`_showUpdateDialog()` 弹出前判断 `Platform.isAndroid && selectAsset() != null`，否则走原「前往更新」外链逻辑（保留现有代码路径）。

settings_page.dart 接入点：`_showUpdateDialog()`（559-634 行）改为根据条件弹新 `UpdateDialog` 或走原外链。

✅ **commit ③**：`设置页更新弹窗支持应用内下载进度与自动安装`（样式调整合并在本次提交，不单独 commit）

## 错误处理汇总

| 场景 | 处理 |
|---|---|
| 网络超时/连接失败 | failed 态 +「下载失败，请检查网络后重试」+ 重试 + GitHub 兜底链接 |
| HTTP 403/404/5xx | 文案带状态码，404 提示前往发布页 |
| 存储不足 | 「存储空间可能不足」 |
| 安装权限被拒/永久拒绝 | 解释弹窗 +「去设置」→ 返回后复查 |
| 文件损坏（大小不符） | 删文件、failed、可重试 |
| 唤起安装器失败 | 提示手动安装 +「前往 GitHub 页面」 |

## 验证

1. `flutter analyze` 无错误；`flutter test`（为 `selectAsset` 纯函数补单测：arm64 设备命中 arm64-v8a、v7a 设备命中 v7a、x86_64 模拟器命中 x86_64、空 assets 返回 null、长令牌优先）
2. **真机/模拟器端到端**：
   - arm64 真机（或当前连接设备）：检查更新 → 弹窗 → 立即更新 → 观察进度条 → 下载完成自动唤起安装器 → 权限首次申请流程正常
   - 权限拒绝路径：拒绝后出现「去设置」引导，从设置返回后复查通过
   - 取消下载 → 回到 confirm 态，再次下载正常
   - 弱网/断网 → failed 态文案与重试、GitHub 兜底链接可用
   - x86_64 模拟器（如有）验证架构匹配落到 `app-x86_64-release.apk`
3. 版本对比提示：测试时需设备版本低于线上 tag（当前 pubspec 1.0.7 == 线上 v1.0.7，验证弹窗流程可临时改本地 version 为 1.0.6 再运行，**验证后还原，不提交**）
