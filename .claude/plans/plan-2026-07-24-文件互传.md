# 文件互传模块 — 技术方案

## 1. 方案对比分析

### 方案 A：手机端内置 HTTP Server（✅ 推荐）

**原理**：Flutter App 内置 HTTP 文件服务器，电脑通过浏览器访问手机 IP 地址上传/下载文件；手机端通过 HTTP API 主动拉取电脑共享目录。

**架构**：
```
手机 (Flutter App)                      电脑 (Windows)
┌───────────────────────┐              ┌────────────────────────┐
│  HTTP Server (shelf)  │◄────────────►│  浏览器访问手机IP       │
│  端口: 8080           │   WiFi局域网  │  输入连接码 → 传文件    │
│  [连接码认证]         │              └────────────────────────┘
│                       │
│  SMB Client           │──────────────►┌────────────────────────┐
│  (smb_connect)        │   账户+密码   │  Windows 隐藏共享       │
│  [专用账户认证]       │              │  PhoneShare$ (不可见)   │
└───────────────────────┘              │  专用账户: phone/xxx    │
                                       └────────────────────────┘
```

**优点**：
- 手机是"主控端"，用户操作全在手机上完成
- 电脑端零安装（浏览器 + 共享文件夹）
- HTTP 协议成熟，Flutter 生态支持好
- `shelf` 包稳定可靠

**缺点**：
- 电脑→手机方向仍需浏览器操作（但由手机端发起连接）
- SMB 库不成熟，需要降级方案

---

### 方案 B：电脑端运行 HTTP Server

**原理**：电脑运行一个轻量 HTTP Server 脚本，Flutter App 作为客户端连接电脑。

**优点**：纯 HTTP，库成熟
**缺点**：需要在电脑上运行额外程序，不满足"纯手机端操作"

---

### 方案 C：WebDAV（IIS）

**原理**：在 Windows 上启用 IIS WebDAV，Flutter 用 `webdav_client` 连接。

**优点**：标准协议，HTTP 友好
**缺点**：IIS 配置复杂（5+ 步骤），不满足"简单"要求

---

### 结论：采用方案 A

### 2.3 核心服务设计

#### 2.3.1 FileServerService（手机端 HTTP 服务器）

```dart
class FileServerService {
  static final instance = FileServerService._();

  // 启动 HTTP 服务器（默认端口 8080），自动生成连接码
  Future<void> start({int port = 8080});

  // 停止服务器
  Future<void> stop();

  // 获取本机 IP 地址
  String? get localIp;

  // 服务器状态
  bool get isRunning;

  // 当前连接码（启动时自动生成 6 位随机数字）
  String? get connectionCode;

  // 刷新连接码（重新生成）
  void refreshCode();
}
```

**连接码认证机制**：

- 服务器启动时生成 6 位随机数字连接码（如 `382916`）
- 电脑浏览器访问 `http://手机IP:8080`，先看到连接码输入页面
- 输入正确后，服务端设置一个 session cookie，后续请求自动通过
- 所有 `/api/*` 接口也需验证 cookie，未认证返回 `401`
- 连接码仅存在于内存中，不持久化，服务器停止即失效
- 用户可手动刷新连接码（踢掉已连接的设备）

**HTTP API 路由**：

| 路由 | 方法 | 认证 | 说明 |
|------|------|------|------|
| `/` | GET | 否 | 连接码输入页面 |
| `/auth` | POST | 否 | 验证连接码，成功后设置 cookie |
| `/home` | GET | 是 | 文件上传/下载 Web 界面 |
| `/api/upload` | POST | 是 | 上传文件到手机 |
| `/api/files` | GET | 是 | 列出手机端可下载文件 |
| `/api/download/:path` | GET | 是 | 下载手机文件 |

Web 界面使用内嵌的简单 HTML（无需额外资源文件），支持拖拽上传。

#### 2.3.2 SMBClientService（SMB 客户端）

```dart
class SMBClientService {
  static final instance = SMBClientService._();

  // 连接到电脑共享
  Future<bool> connect({
    required String host,
    required String share,
    String? username,
    String? password,
  });

  // 浏览目录
  Future<List<RemoteFile>> listDirectory(String path);

  // 下载文件到本地
  Future<void> downloadFile({
    required String remotePath,
    required String localPath,
    void Function(int received, int total)? onProgress,
  });

  // 上传文件到电脑
  Future<void> uploadFile({
    required String localPath,
    required String remotePath,
    void Function(int sent, int total)? onProgress,
  });

  // 断开连接
  Future<void> disconnect();
}
```

**降级方案**：如果 `smb_connect` 库不稳定，降级为：
1. 手机端生成一个 `.bat` 脚本，用户在电脑上运行一次即可开启共享
2. 手机端通过 `Process.run('net', ['use', ...])` 尝试连接（仅 Windows 桌面端）

**Windows 共享安全配置**（用户首次使用时引导）：
- 共享文件夹名使用 `$` 后缀（如 `PhoneShare$`），使其在网络邻居中隐藏
- 创建专用低权限本地账户（如用户名 `phone`），仅授予该共享文件夹的读写权限
- 手机端保存该账户的用户名和密码到 `mod_file_transfer_configs` 表
- App 首次连接时引导用户输入电脑 IP、共享名、用户名、密码

### 2.7 首次使用引导流程

用户首次使用"访问电脑文件"功能时，App 引导完成以下配置：

```
步骤 1：输入电脑 IP 地址（如 192.168.1.100）
        ↓
步骤 2：输入共享文件夹名（默认建议 PhoneShare$）
        ↓
步骤 3：输入专用账户用户名/密码（如 phone / 自定义密码）
        ↓
步骤 4：App 自动生成 .bat 脚本并提供复制/分享方式
        用户在电脑上以管理员身份运行一次
        脚本内容：创建专用账户 + 创建隐藏共享 + 设置权限
        ↓
步骤 5：测试连接 → 成功后保存配置
```

**.bat 脚本内容示例**（App 自动生成，参数化）：
```bat
@echo off
echo === 文件互传 - 电脑端配置脚本 ===
echo.

:: 创建专用账户
net user phone MyPassword123 /add
echo [OK] 已创建账户: phone

:: 创建共享文件夹
mkdir C:\PhoneShare
net share PhoneShare$=C:\PhoneShare /GRANT:phone,FULL
echo [OK] 已创建隐藏共享: PhoneShare$

:: 设置 NTFS 权限（移除 Users 组，仅保留 phone 账户）
icacls C:\PhoneShare /inheritance:r
icacls C:\PhoneShare /grant:r phone:(OI)(CI)F
icacls C:\PhoneShare /grant:r Administrators:(OI)(CI)F
echo [OK] 已设置文件夹权限

echo.
echo 配置完成！请返回手机 App 测试连接。
pause
```

### 2.8 安全设计汇总

| 组件 | 安全机制 | 实现方式 |
|------|----------|----------|
| HTTP Server | 连接码认证 | 6 位随机码 + session cookie + API token |
| SMB 连接 | 账户密码 | 专用低权限 Windows 账户 |
| 共享文件夹 | 隐藏共享 | 共享名 `$` 后缀，网络邻居不可见 |
| 文件权限 | NTFS 权限 | 仅专用账户和 Administrators 有权限 |
| 配置存储 | 本地加密 | 密码在 SQLite 中加密存储（可选） |

## 4. 风险和降级策略

| 风险 | 影响 | 降级方案 |
|------|------|----------|
| smb_connect 库不稳定 | 无法访问电脑文件 | 降级为 .bat 脚本方案，手机端仅提供 HTTP Server |
| Android 存储权限限制 | 无法读写文件 | 使用 SAF（Storage Access Framework）选择目录 |
| 端口被占用 | HTTP Server 无法启动 | 自动尝试下一个端口，或提示用户 |
| WiFi 隔离 | 手机电脑无法通信 | 提示用户检查路由器 AP 隔离设置 |
| .bat 脚本被拦截 | 安全软件阻止脚本运行 | 提示用户临时关闭安全软件，或手动配置步骤说明 |
| 连接码泄露 | 他人可访问手机文件 | 提供刷新连接码按钮，踢掉已连接设备 |
