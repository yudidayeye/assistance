## 一、产品概述

轻量级**分阶段周期记账**模块。用户在一个发薪周期内，按自定义时间段（通常按周）分阶段记录消费。每个阶段有独立的本金、支出、余额，阶段间本金链式传递。配合图表可视化。

---

## 二、核心概念

### 2.1 记账周期（Period）

- 一个发薪周期，有**起止日期**，由全局设置的**发薪日**决定默认值
  - **开始日期** = 当月发薪日
  - **结束日期** = 下月发薪日前一天
- 新建周期时可手动修改起止日期（**不可清空**）
- **允许提前创建未来周期**：当前周期未结束时也可新建下一个周期（如7月的周期还在进行中，可以提前创建8月的周期），但**不允许日期重叠**
- 一个周期内包含多个**阶段（Stage）**，按时间顺序排列

### 2.2 阶段（Stage）

- 周期内的一个时间段，**必须有结束日期**
- 新建周期时**自动创建阶段**，默认按周（周一到周日）划分
  - 最后一个阶段的结束日期 = 周期结束日期
  - 若周期不满整周，最后一个阶段自动缩短
- 每个阶段的**本金** = 上一阶段的**余额** + 本阶段**追加金额**
  - 第一阶段的本金 = 周期的**初始本金**
- 阶段内可记录购物/其他支出，手动填入余额，系统倒推生活支出

### 2.3 本金体系（链式传递）

```
阶段1 本金  = 周期初始本金
阶段2 本金  = 阶段1 余额 + 阶段2 追加金额
阶段3 本金  = 阶段2 余额 + 阶段3 追加金额
...
```

| 名称 | 说明 |
|------|------|
| **周期初始本金** | 新建周期时填入，作为第一阶段本金 |
| **阶段追加金额** | 每个阶段可有多条追加，每条有金额+原因 |
| **阶段本金** | 上一阶段余额 + 本阶段追加金额（第一阶段=初始本金） |
| **总本金** | 初始本金 + Σ所有阶段的追加金额 |

### 2.4 支出分类（每阶段独立）

| 分类 | 输入方式 | 说明 |
|------|----------|------|
| **购物** | 逐条记录（金额 + 描述），默认分类 | 可多条 |
| **其他** | 逐条记录（金额 + 描述） | 可多条 |
| **生活** | 系统倒推计算 | 生活 = 阶段本金 − 购物 − 其他 − 余额 |
| **余额** | **用户手动输入** | 纯手动，未填时显示缺省（—） |

> **生活日均** = 阶段生活支出 ÷ 阶段天数（系统自动算）
> 当余额未填入时，生活支出和生活日均均显示缺省

### 2.5 计算逻辑（每个阶段独立）

```
阶段本金     = 上一阶段余额 + Σ本阶段追加金额（第一阶段 = 初始本金）
购物总额     = Σ本阶段购物明细
其他总额     = Σ本阶段其他明细
余额        = 用户手动输入（未填显示 "—"）
生活支出     = 阶段本金 − 购物总额 − 其他总额 − 余额（余额未填时显示 "—"）
生活日均     = 生活支出 ÷ 阶段天数（余额未填时显示 "—"）
阶段天数     = 结束日期 − 开始日期 + 1
```

> **关键约束**：余额是纯手动字段。未填余额时，该阶段的生活支出和日均均显示缺省。
> 阶段间本金链式传递：下一阶段本金依赖上一阶段余额。

## 三、数据模型

### 3.1 周期表 `mod_period_book_periods`（精简）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | INTEGER | PK AUTO | 周期ID |
| `start_date` | TEXT | NOT NULL | 周期开始日期 |
| `end_date` | TEXT | NOT NULL | 周期结束日期 |
| `base_amount` | REAL | NOT NULL | 初始本金（第一阶段本金） |
| `is_closed` | INTEGER | NOT NULL DEFAULT 0 | 是否已结束 |
| `created_at` | TEXT | NOT NULL | 创建时间 |
| `updated_at` | TEXT | NOT NULL | 更新时间 |

> 删除旧字段：`in_progress_date`、`balance`（移至阶段表）

### 3.2 阶段表 `mod_period_book_stages`（新增）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | INTEGER | PK AUTO | 阶段ID |
| `period_id` | INTEGER | FK → periods.id, NOT NULL | 所属周期 |
| `start_date` | TEXT | NOT NULL | 阶段开始日期 |
| `end_date` | TEXT | NOT NULL | 阶段结束日期 |
| `balance` | REAL | NULLABLE | 本阶段余额（手动输入） |
| `sort_order` | INTEGER | NOT NULL | 排序序号（1, 2, 3...） |
| `created_at` | TEXT | NOT NULL | 创建时间 |
| `updated_at` | TEXT | NOT NULL | 更新时间 |

### 3.3 追加记录表 `mod_period_book_additions`（修改）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | INTEGER | PK AUTO | 记录ID |
| `stage_id` | INTEGER | FK → stages.id, NOT NULL | 所属阶段 |
| `amount` | REAL | NOT NULL | 追加金额 |
| `reason` | TEXT | NOT NULL | 追加原因（必填） |
| `created_at` | TEXT | NOT NULL | 创建时间 |

> 关联从 period_id 改为 stage_id，追加记录归属于具体阶段。

### 3.4 支出明细表 `mod_period_book_expenses`（修改）

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | INTEGER | PK AUTO | 记录ID |
| `stage_id` | INTEGER | FK → stages.id, NOT NULL | 所属阶段 |
| `category` | TEXT | NOT NULL | 分类：'shopping' / 'other' |
| `amount` | REAL | NOT NULL | 金额（正数） |
| `description` | TEXT | NOT NULL | 描述 |
| `created_at` | TEXT | NOT NULL | 创建时间 |

> 关联从 period_id 改为 stage_id，支出归属于具体阶段。

### 3.5 全局设置项

| 键名 | 默认值 | 说明 |
|------|--------|------|
| `period_book_payday` | `10` | 发薪日（1~31） |

## 四、页面设计

### 4.1 当前周期详情页（入口页）

进入记账模块后直接展示当前周期的阶段详情。

**顶部导航栏：**
- 周期日期范围标题（如 `06月09日 ~ 07月10日`）
- 右侧按钮：**历史记录**、**编辑周期**（跳转编辑页面）

**顶部汇总卡片：**
| 项目 | 值 | 来源 | 交互 |
|------|-----|------|------|
| 总本金 | ¥3200 | 初始本金 + Σ追加 | **可点击**，弹出详情浮层 |
| 购物 | ¥-678.85 | Σ所有阶段购物 | |
| 其他 | ¥-99.8 | Σ所有阶段其他 | |
| 余额 | ¥355.91 | 最新阶段余额（未填显示 —） | |
| 生活 | ¥-520.32 | Σ所有阶段生活（余额未填显示 —） | |

**总本金点击详情（底部弹出浮层）：**

```
╔════════════════════════════╗
║     总本金构成详情          ║
╠════════════════════════════╣
║  初始本金          ¥2800   ║
║  ───────────────────────── ║
║  第一周追加        ¥0      ║
║  第二周追加        ¥400    ║
║    └ 第二周补              ║
║  第三周追加        ¥0      ║
║  ...                       ║
║  ───────────────────────── ║
║  合计             ¥3200   ║
╚════════════════════════════╝
```

> 列出每个阶段的追加明细（金额+原因），无追加的阶段显示 ¥0 并折叠原因。

**阶段列表（核心）：**

每个阶段一个卡片，按时间顺序排列：

```
第一周 (06.09~06.15)
  本金: 2800
  购物: -678.85（展开明细列表）
  其他: —
  余额: 2017.13 [编辑按钮]
  生活: -104.02/7 = -14.86
  追加: —

第二周 (06.16~06.28)
  本金: 2017.13+400 = 2417.13
  购物: -636.16（展开明细列表）
  其他: -99.8（展开明细列表）
  余额: 1401.49 [编辑按钮]
  生活: -520.32/13 = -40.02
  追加: +400 第二周补
```

- 阶段卡片可展开/收起明细
- 每条明细左滑可删除
- 阶段卡片底部操作：「追加本金」「批量记账」「编辑余额」
- 列表末尾：「添加阶段」按钮

**图表区域：**
- 支出占比饼图（当前选中阶段 or 全周期）
- 余额趋势折线图（各阶段余额变化）

### 4.2 历史周期列表页

- 按开始日期倒序
- 每行：日期范围 + 总本金 + 最新余额
- 点击 → 进入该周期详情页（只读模式）

### 4.3 新建周期页

> 任何时候都可以新建未来周期（无需等待当前周期结束），但**不允许与已有周期日期重叠**。

表单字段：
1. **开始日期** — 默认下月发薪日（如有当前周期则接在其后），可修改
2. **结束日期** — 默认再下月发薪日前一天，可修改但**不可清空**
3. **初始本金** — 数字键盘输入

保存前校验：
- 检查是否与已有周期日期重叠，若重叠提示用户

保存后系统自动：
- 创建周期记录
- 按周（周一到周日）自动拆分阶段
- 最后一个阶段结束日期 = 周期结束日期
- 若周期不满整周，最后一个阶段自动缩短

### 4.4 编辑周期页（新增）

> 复用新建周期页的表单结构，改为**页面形式**（非弹窗），所有字段均可修改。

表单字段：
1. **开始日期** — 可修改（但若已有阶段数据，修改开始日期需校验不能晚于最早阶段的开始日期）
2. **结束日期** — 可修改但**不可清空**（不能早于最晚阶段的结束日期）
3. **初始本金** — 可修改

保存时：
- 若结束日期**延长**：自动在末尾追加新阶段（按周拆分）
- 若结束日期**缩短**：提示用户确认，被删除的阶段内的支出数据将一并删除
- 若开始日期**延长**：提示用户确认，被删除的阶段内的支出数据将一并删除
- 其他情况：仅更新周期信息，不自动调整阶段

> 页面入口：周期详情页顶部导航栏的「编辑周期」按钮。

### 4.5 添加阶段

- 开始日期 = 上一阶段结束日期 + 1天
- 结束日期 = 开始日期 + 6天（默认一周），但不超过周期结束日期
- 本金自动显示为：上一阶段余额（只读提示）

> 支持一次操作记录多条支出，用表格形式展示待提交条目，减少重复操作。

1. **先选阶段**：顶部下拉框选择要记入的阶段

4. **一键保存**：点击「保存」一次性提交表格中所有条目
5. **清空**：清空当前表格（不影响已保存数据）

## 五、自动创建阶段算法

```
输入：周期 start_date, end_date, base_amount

阶段列表 = []
current_date = start_date
sort = 1

while current_date <= end_date:
    stage_end = min(current_date + 6天, end_date)  // 一周或到周期末尾
    
    创建阶段:
        start_date = current_date
        end_date = stage_end
        balance = null
        sort_order = sort
    
    current_date = stage_end + 1天
    sort += 1
```

示例（发薪日=10号，周期 2026-06-09 ~ 2026-07-09）：
```
阶段1: 06-09 ~ 06-15 (7天, 周一到周日)
阶段2: 06-16 ~ 06-22 (7天)
阶段3: 06-23 ~ 06-29 (7天)
阶段4: 06-30 ~ 07-06 (7天)
阶段5: 07-07 ~ 07-09 (3天, 不足一周自动缩短)
```

## 附录：截图数据结构对照

```

  → periods: start_date=2026-06-09, end_date=2026-07-10, base_amount=2800

  → stages: start=06-09, end=06-15, sort=1

  → 生活 = 2800 - 678.85 - 0 - 2017.13 = 104.02

阶段2: 第二周 (06.16~06.28)
  → stages: start=06-16, end=06-28, sort=2

  → expenses: shopping 合计 -636.16, other 合计 -99.8

  → 生活 = 2417.13 - 636.16 - 99.8 - 1401.49 = 279.68
  → 生活日均 = 279.68 / 13 = 21.51
```
