# 开发计划 — 全局导航/Tab 统一 + 生理期记录页间距微调

> 基于 `requirement-260626-4.md`

---

## 概述

本次优化聚焦两类问题：

1. **生理期记录页局部 UI 间距与文案精简**：让日期详情卡片、日历卡片内部信息更紧凑，去掉不必要文案。
2. **全局导航与 Tab 栏统一**：统一页面标题字号与导航按钮风格，下方 Tab 栏采用应用内更常见、更贴合主题的样式。

需求文档中的「周期统计页 / 我的页 / 设置页 / 工具箱页」未列出单独功能点，本计划将其纳入 **导航栏统一样式巡检范围**，只调整导航相关样式，不额外扩展功能。

---

## 阶段 A：生理期记录页 — 日期详情卡片优化

### A.1 增加日期详情卡片上边距

**目标**：日期详情卡片与上方日历卡片之间留出更自然的呼吸感，避免内容过于贴近。

**改动文件**：
- `lib/modules/period_tracker/widgets/date_detail_panel.dart`
- 如间距由父级控制，则同步检查：`lib/modules/period_tracker/pages/calendar_page.dart`

**实施步骤**：
1. 定位 `DateDetailPanel` 根容器的 `margin` 或外层 `Padding`。
2. 增加顶部间距，建议从当前值上调 `4~8px`，保持整体低密度、柔和健康陪伴感。
3. 确保底部间距不被同步放大，避免页面整体变得松散。

**验收标准**：
- 日期详情卡片与日历卡片之间不再显得拥挤。
- 页面滚动区域没有出现明显过大空白。

---

### A.2 去掉“姨妈走了”文字

**目标**：精简日期详情卡片操作文案，减少重复或情绪化表达。

**改动文件**：
- `lib/modules/period_tracker/widgets/date_detail_panel.dart`

**实施步骤**：
1. 搜索并定位 `姨妈走了` 文案所在的 `Text`、按钮、Switch 副标题或状态标签。
2. 移除该文字展示。
3. 若该文案承载“结束经期”操作含义，则保留操作能力，仅改变展示方式：
   - 可改为仅显示开关状态；或
   - 使用更中性的短文案，如确实需要可考虑「结束记录」，但优先按需求直接移除。
4. 确保删除文案后 Row/Column 不出现多余空隙。

**验收标准**：
- 页面中不再出现“姨妈走了”。
- 原有记录经期开始/结束的交互不受影响。

## 阶段 B：生理期记录页 — 日历卡片间距优化

### B.1 减小星期行距离下方日历网格的距离

**目标**：让星期标题与日期网格关系更紧密，减少视觉断层。

**改动文件**：
- `lib/modules/period_tracker/widgets/period_calendar.dart`

**当前参考位置**：
- 星期标题 Row 下方存在 `SizedBox(height: 6)`。

**实施步骤**：
1. 将星期行与 GridView 之间的间距适当减小，例如 `6 → 2/3/4`。
2. 保持星期行文字清晰，不压迫日期格子。
3. 如日期格子 `mainAxisSpacing` 已较小，不同步压缩网格内部间距，避免误触或拥挤。

**验收标准**：
- 星期行与日期网格更紧凑。
- 日历整体仍保持柔和、低密度视觉。

---

### B.2 减小预测标签行距离上方日历网格的距离

**目标**：让底部「经期 / 预测经期 / 排卵期 / 易孕期」图例与日历卡片内容更统一。

**改动文件**：
- `lib/modules/period_tracker/widgets/period_calendar.dart`

**当前参考位置**：
- 图例区域前存在 `SizedBox(height: 8)`。
- `_buildLegendSection` 内部存在 `padding: EdgeInsets.symmetric(horizontal: 12, vertical: 8)`。

**实施步骤**：
1. 将 GridView 与图例区之间的间距适当减小，例如 `8 → 4`。
2. 如仍显得偏松，再微调 `_buildLegendSection` 的 vertical padding，例如 `8 → 6`。
3. 保持图例可读性，不压缩图例文字字号。

**验收标准**：
- 预测标签行距离上方日历区域更近。
- 图例没有拥挤或贴边问题。

## 阶段 C：Tab 栏样式统一

### C.1 下方 Tab 栏改为应用常用样式

**目标**：底部 Tab 栏采用项目内更通用的柔和主题样式，避免与页面背景割裂。

**改动文件**：
- `lib/shared/widgets/toolbox_bottom_nav.dart`
- 如需同步主题默认值：`lib/core/theme/app_theme.dart`

**实施步骤**：
1. 检查当前 `ToolboxBottomNav` 是否已经使用主题 token：
   - `appTheme.cream`
   - `appTheme.creamDark`
   - `appTheme.cardBackground`
   - `appTheme.primary / primaryDark`
2. 采用应用常用 Tab 风格：
   - 外层背景跟随页面主题，避免纯白硬背景。
   - 内层使用柔和卡片/胶囊容器。
   - 选中态使用主色低透明背景 + 主色深色文字/图标。
   - 未选中态使用 `earthLight` 或 `earthMedium`。
3. 保持 `HitTestBehavior.opaque`，确保整个 tab 区域可点击。
4. 避免高饱和、高对比、强阴影；阴影仅保留极轻柔光。

**验收标准**：
- 切换 4 套主题时，Tab 栏颜色能跟随主题变化。
- 选中态清晰，但不刺眼。
- 点击文字、图标、空白区域均可切换。

## 阶段 D：导航栏样式统一

### D.1 统一所有页面导航栏标题字号

**目标**：所有页面导航标题减小，避免标题过大造成压迫感；统一为克制、安静的风格。

**主要改动文件**：
- `lib/core/theme/app_theme.dart`
- `lib/pages/main_shell_page.dart`
- `lib/pages/profile_page.dart`
- `lib/core/settings/settings_page.dart`
- `lib/modules/accounting/pages/entry_page.dart`
- `lib/modules/accounting/pages/add_page.dart`
- `lib/modules/accounting/pages/stats_page.dart`
- `lib/modules/accounting/pages/category_settings.dart`
- `lib/modules/period_tracker/pages/calendar_page.dart`
- `lib/modules/period_tracker/pages/stats_page.dart`

**实施步骤**：
1. 先统一全局 `AppTheme.appBarTheme.titleTextStyle`：
   - 字号建议：`22`
   - 字体建议：`GoogleFonts.dmSans()`
   - 字重：`FontWeight.w700`
   - 字距：`-0.3`
2. 巡检自定义 Header 页面，重点查找：
   - `GoogleFonts.playfairDisplay()`
   - `fontSize: 28`
   - `fontSize: 26`
   - 自绘返回按钮 + 标题 Row
3. 对自定义 Header 统一为同一标题规格：
   - 标题字号 `22`
   - 标题字体 `DM Sans`
   - 返回按钮 `40×40` 或与现有主题按钮一致
   - 返回按钮背景 `appTheme.primary.withValues(alpha: 0.08~0.10)`
   - 返回按钮图标颜色优先使用 `appTheme.primaryDark` 或 `appTheme.earthMedium`，同一页面组内保持一致
4. 首页/工具箱页无 AppBar，按同样规则处理自绘标题。
5. 我的页如保留更具品牌感的字体，需要确认是否属于例外；若严格按需求，则同步降为统一规格。

**验收标准**：
- 页面标题不再出现明显过大的 `28px` 导航标题。
- 设置页、统计页、模块详情页返回按钮与标题风格一致。
- 工具箱页、我的页顶部标题与其它页面视觉层级协调。

## 风险与注意事项

1. **不要扩大需求范围**：周期统计页、我的页、设置页、工具箱页仅做导航样式巡检，不新增业务功能。
2. **避免硬编码白色背景**：优先使用 `appTheme.cardBackground`、`cream`、`creamDark`。
3. **避免标题过度装饰化**：导航标题以清晰克制为主，减少大字号 Playfair Display 的使用。
4. **保留可点击热区**：Tab 栏样式调整时不能缩小点击区域。
5. **文案删除不等于功能删除**：去掉“姨妈走了”只影响展示，不应破坏结束经期记录的业务逻辑。
