# 需求：工具箱顶部下拉菜单 + 展示样式 + 模块管理独立页（2026-09-04）

## 背景
工具箱页右上角齿轮直达 `/settings`，是唯一的「设置」入口；模块管理（启用/固定/拖拽排序）整个区块内嵌在 `/settings` 页顶部。用户希望把「模块相关设置」收敛到工具箱自身，把重型管理区块从设置页抽走。

## 目标
1. 去掉工具箱齿轮「直达设置」的跳转，改为**下拉菜单**，含两个设置项：
   - **展示样式**：模块卡片在 单列 / 双列 间切换，偏好持久化、重启保留。
   - **模块管理**：进入新独立页面。
2. `/settings` 的模块管理区块整体移除；模块管理功能迁移到**新独立页**，仅由该下拉菜单进入。`/settings` 齿轮入口保留（主题/数据/隐私/更新等仍在设置页）。

## 需求点
1. 工具箱 AppBar 齿轮图标外观不变，点击弹 `PopupMenuButton`：双列展示 / 单列展示（当前模式前带 ✓）+ 分隔线 + 模块管理。
2. 展示样式偏好存 `app_settings.toolbox_columns`（'1'/'2'，默认双列），随 JSON 导入/导出保持一致；经 SettingsController 通知即时重排。
3. 双列 = 维持现状（FeaturedCard 方块网格，0.88）；单列 = **横版行卡片**（已确认）：整张圆角容器卡，逐模块一行（左图标色块 + 主题色标题与摘要两行 + 末尾箭头），行间细分隔线；摘要随模块数据实时刷新。
4. 新页「模块管理」：完整承载 启用开关 / 固定开关 / 拖拽排序（含列头、拖拽代理），能力与现设置页一致。
5. `/settings` 移除模块管理区后其余区块（主题/数据/功能/关于）原样保留。

## 约束
- 复用现有模块化架构与设计 token（AppThemeExtension、SectionCard、AppScrollScaffold、module.icon.build）。
- 单列行组件的摘要绑定沿用 FeaturedCard 的 3-service listener 模式。
- 拖拽排序沿用项目内 `ReorderableListView.builder` + `onReorderItem`。
- 不新增 pub 依赖、不改原生配置。
