# 周期记账模块 — 需求设计文档

> 替代现有 accounting 模块，全新设计。
> 创建日期：2026-07-06

---

## 一、产品概述

轻量级**周期记账**模块，以"发薪周期"为时间单位，支持自定义周期起止、多次追加本金、分类支出记录，配合图表可视化。余额由用户手动填入，未填时显示缺省。

---

## 二、核心概念

### 2.1 记账周期（Period）

- 每个周期有**起止日期**，起止日期由全局设置的**发薪日**决定默认值
- 默认行为：
  - **开始日期** = 当月发薪日（如发薪日为10号 → 当月10号）
  - **结束日期** = 下月发薪日前一天（如发薪日为10号 → 下月9号）
- 新建周期时可手动修改结束日期（如提前结束或延后），**不可清空**
- 周期状态：
  - **进行中**：当前正在记账的周期（最近新建的），余额数据手动填入，未填时显示缺省（—）
  - **已结束**：用户手动标记结束，数据定格
- 允许在周期中途（未结束时）新建下一周期
- 周期天数 = 系统自动计算（进行中日期 / 结束日期 − 开始日期 + 1）

### 2.2 本金体系

| 名称 | 说明 |
|------|------|
| **总本金** | 显示名称，= 初始本金 + Σ追加金额 |
| **初始本金** | 新建周期时手动填入 |
| **追加金额** | 周期内多次追加，每条记录金额 + 原因（必填） |

### 2.3 支出分类

| 分类 | 输入方式 | 说明 |
|------|----------|------|
| **购物** | 逐条记录（金额 + 描述），默认分类 | 可多条 |
| **其他** | 逐条记录（金额 + 描述） | 可多条 |
| **生活** | 系统倒推计算 | 生活 = 总本金 − 购物总额 − 其他总额 − 余额 |
| **余额** | **用户手动输入** | 纯手动，未填时显示缺省（—），不参与自动计算 |

> **生活日均** = 生活支出总额 ÷ 周期天数（系统自动算）
> 当余额未填入时，生活支出和生活日均均显示缺省

### 2.4 计算逻辑

```
总本金      = 初始本金 + Σ追加金额
购物总额     = Σ购物明细金额
其他总额     = Σ其他明细金额
余额        = 用户手动输入（未填时显示 "—"）
生活支出     = 总本金 − 购物总额 − 其他总额 − 余额（余额未填时显示 "—"）
生活日均     = 生活支出 ÷ 周期天数（余额未填时显示 "—"）
```

> **关键约束**：余额是纯手动字段，系统绝不自动修改或推算。
> 只有用户主动编辑余额时才会更新。未填入时，生活支出和生活日均均显示缺省。

## 三、数据模型

### 3.1 周期表 `mod_period_book_periods`

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | INTEGER | PK AUTO | 周期ID |
| `start_date` | TEXT | NOT NULL | 开始日期 (yyyy-MM-dd) |
| `end_date` | TEXT | NOT NULL | 结束日期 (yyyy-MM-dd) |
| `in_progress_date` | TEXT | NULLABLE | 进行中日期 (yyyy-MM-dd) |
| `base_amount` | REAL | NOT NULL | 初始本金 |
| `balance` | REAL | NULLABLE | 余额（手动输入） |
| `is_closed` | INTEGER | NOT NULL DEFAULT 0 | 是否已结束（0=进行中, 1=已结束） |
| `created_at` | TEXT | NOT NULL | 创建时间 |
| `updated_at` | TEXT | NOT NULL | 更新时间 |

### 3.2 追加记录表 `mod_period_book_additions`

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | INTEGER | PK AUTO | 记录ID |
| `period_id` | INTEGER | FK → periods.id | 所属周期 |
| `amount` | REAL | NOT NULL | 追加金额 |
| `reason` | TEXT | NOT NULL | 追加原因（必填） |
| `created_at` | TEXT | NOT NULL | 创建时间 |

### 3.3 支出明细表 `mod_period_book_expenses`

| 字段 | 类型 | 约束 | 说明 |
|------|------|------|------|
| `id` | INTEGER | PK AUTO | 记录ID |
| `period_id` | INTEGER | FK → periods.id | 所属周期 |
| `category` | TEXT | NOT NULL | 分类：'shopping' / 'other' |
| `amount` | REAL | NOT NULL | 金额（正数） |
| `description` | TEXT | NOT NULL | 描述 |
| `created_at` | TEXT | NOT NULL | 创建时间 |

### 3.4 全局设置项

| 键名 | 默认值 | 说明 |
|------|--------|------|
| `period_book_payday` | `10` | 发薪日（1~31），用于新建周期时自动计算默认起止日期 |

> 存储在 `app_settings` 表中（项目已有的全局 key-value 表）。
> 发薪日修改后，**仅影响后续新建周期**，不改变已有周期的起止日期。

### 3.5 表名规范

按项目约定，模块表前缀为 `mod_period_book_`（module_id = `period_book`）。

## 四、页面设计

### 4.1 当前周期详情页（入口页）

进入记账模块后直接展示当前进行中的周期详情。若无任何周期，显示空状态引导创建。

**顶部导航栏：**
- 日期范围标题（如 `06月09日 ~ 07月10日`）
- 右侧按钮：**历史记录**（跳转到历史周期列表）、**编辑**（修改结束日期 / 进行中日期）

**汇总区域（卡片）：**
| 项目 | 值 | 来源 |
|------|-----|------|
| 总本金 | ¥3200 | 初始 + 追加 |
| 购物 | ¥-678.85 | Σ购物明细 |
| 其他 | ¥-99.8 | Σ其他明细 |
| 余额 | ¥2017.13 | **手动输入**（未填显示 —） |
| 生活 | ¥-520.32 | 总本金−购物−其他−余额（余额未填时显示 —） |
| 生活日均 | ¥-14.86 | 生活÷天数（余额未填时显示 —） |

> 余额字段旁提供编辑按钮，点击弹出数字键盘供用户修改。

**追加记录区域：**
- 列表展示每次追加（金额 + 原因 + 时间）
- "追加本金"按钮

**支出明细区域（分组展示）：**
- 购物分组：逐条列出（-88 盒马会员）
- 其他分组：逐条列出（-99.8 保险）
- 每条明细左滑/长按可删除
- "记一笔"按钮（默认分类=购物，可切换为其他）

**图表区域：**
- 支出占比饼图（购物 / 其他 / 生活）
- 余额趋势折线图（跨周期）

### 4.2 历史周期列表页

从详情页顶部导航栏进入，展示所有已结束的周期。

- 按开始日期倒序排列
- 每行显示：日期范围 + 总本金 + 余额（未填显示 —）
- 点击任一条目 → 进入该周期的详情页（只读模式）
- 详情页提供返回按钮回到历史列表

### 4.3 新建周期页

表单字段：
1. **开始日期** — 默认当月发薪日（如10号），可修改（日期选择器）
2. **结束日期** — 默认下月发薪日前一天（如9号），可修改但**不可清空**（日期选择器）
3. **初始本金** — 数字键盘输入
4. **余额** — 可选，留空则显示缺省（—），后续可在详情页随时编辑

### 4.4 设置页新增项

在现有设置页中新增周期记账设置区域：

| 设置项 | 说明 | 默认值 |
|--------|------|--------|
| **发薪日** | 每月几号发薪（1~31） | 10 |

> 点击弹出数字选择器，确认后保存到 `app_settings` 表。

## 五、进行中日期逻辑

```
有进行中日期 → 周期天数 = 进行中日期 - 开始日期 + 1
无进行中日期 → 周期天数 = 结束日期 - 开始日期 + 1
```

- 用户可在周期详情页设置/清除进行中日期
- 清除进行中日期后，自动回退到结束日期计算
- **进行中日期**的作用：周期未结束但想提前"截断"计算时使用（如只记到7月5号的数据）
